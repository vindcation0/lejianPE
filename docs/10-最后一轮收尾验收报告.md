## 4. 网络隔离验收

通过 [`tests/network_guard.py`](../tests/network_guard.py) 与专项测试套件 [`tests/test_network_guard.py`](../tests/test_network_guard.py)（N01～N14）完成验证：

### 4.1 隔离屏障机制与拦截范围
- **底层 Socket 拦截**：
  - `socket.socket.connect`：阻断公网 TCP 连接；
  - `socket.socket.connect_ex`：阻断公网非阻塞/状态码连接，防止通过状态码嗅探绕过；
  - `socket.socket.sendto`：拦截 UDP 数据包发送，阻断向外部 IP 或外部 UDP DNS (如 8.8.8.8:53) 发包；
  - `socket.create_connection`：前置拦截高层便捷连接建立。
- **DNS 解析入口全覆盖拦截**：
  - `socket.getaddrinfo`：在发起底层系统 DNS 查询前拦截外部域名；
  - `socket.gethostbyname`：拦截常规外部域名解析；
  - `socket.gethostbyname_ex`：拦截扩展外部域名解析。
- **HTTP 客户端与代理穿透拦截**：
  - 针对 `http.client.HTTPConnection.connect` 与 `request` 进行双重校验，即使通过本地 HTTP 代理试图访问外部域名或公网 IP，依然在协议层被强制阻断。
- **本地回环白名单收紧**：
  - 严格剔除通配地址 `0.0.0.0` 和 `::` 作为连接目标；
  - 仅放行回环地址：`127.0.0.0/8`（IPv4 Loopback）、`localhost`、`::1`（IPv6 Loopback）以及 Unix Domain Socket（`AF_UNIX`）。
- **能力边界说明**：
  - 本网络屏障工作于 Python 标准库层级（`socket`、`http.client`、`urllib`）；
  - 本实现不宣称提供操作系统内核级别（如 iptables / eBPF / 容器网络沙箱）的绝对硬件网络隔离。

## 7. 遗留问题与边界说明

严格遵循实事求是原则记录当前系统边界与未验证事项：

1. **生产真实服务端操作未验证边界**：
   - **离线单元测试已验证范围**：通过 A16～A20、A34～A36、U01～U12 等用例，在本地 Mock 环境下完整覆盖了 Token 临期检测、RefreshToken 轮换、雙重备份容灾、UNKNOWN 状态机熔断与离线对账逻辑；
   - **生产服务端未验证边界**：
     - **真实服务端 Token 自动刷新与 RefreshToken 轮换**：为保障当前用户的真实账号会话长期可用，未向生产服务端发起故意使 Token 过期并触发真实刷新的破坏性调用；
     - **真实账号密码全量登录调用**：逆向信封算法在离线单元测试中经由 A01～A15 与标准向量充分验证，但未向官方生产服务器频繁提交真实密码发起高频登录测试，以防触发学校官方服务端的账号风控或封禁限制。
2. **测试网络隔离屏障能力边界**：
   - 屏障拦截严格依托 Python 标准库的 Monkey Patching（`socket`、`http.client`、`urllib`）；
   - 不代表操作系统内核级别（如容器 cgroups / iptables / seccomp）的网络隔离；
   - 严禁将针对 Python 层的测试隔离屏障宣传为宿主机层面的绝对物理隔离。
3. **计划内收尾任务闭环**：
   - Gitleaks 忽略规则收紧（删除宽泛行级规则，保留精准提交指纹）；
   - 全局网络隔离屏障补强（覆盖 `connect_ex`、UDP `sendto`、额外 DNS 入口，修复 `0.0.0.0`/`::` 白名单）；
   - 控制台编码异常兜底修复与 E01～E04 专项测试；
   - 验收文档与实际测试日志、CI 数据保持完全一致。
