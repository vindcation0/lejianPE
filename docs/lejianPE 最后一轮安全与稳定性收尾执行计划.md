# 三、任务一：收紧 Gitleaks 忽略规则

**优先级：P0**

```

tests/test_auth.py
```

## 3.1 当前发现的问题

目前 `.gitleaksignore` 存在以下规则：

```
state.json:generic-api-key:2
state.json:generic-api-key:3
```

这类基于文件路径、规则和行位置的忽略规则存在潜在风险。

如果未来真实 Token 恰好出现在被忽略的位置，可能造成安全扫描遗漏。

`state.json` 属于敏感状态文件，不应该通过宽泛忽略规则降低扫描覆盖率。

## 3.2 修改要求

### A. 删除 state.json 忽略规则

删除：

```
state.json:generic-api-key:2
state.json:generic-api-key:3
```

要求：

- 不再为整个 state.json 的固定行设置忽略。
- 不允许通过扩大忽略范围解决误报。
- 不允许降低 Gitleaks 扫描范围。

### B. 审查所有 gitleaks

搜索整个仓库：

```
git grep -n "gitleaks:allow"
```

逐个审查：

- `tools/login_envelope.py`
- `tests/test_auth.py`
- 其他可能存在的文件。

区分：

1. 确实属于公开协议常量的内容。
2. 单元测试中的虚拟占位数据。
3. 真实敏感凭据。

对确实需要豁免的内容，必须说明豁免原因。

优先考虑精确指纹豁免，避免扩大豁免范围。

### C. 评估忽略注释绕过风险

检查当前固定版本 Gitleaks 是否支持：

```
--ignore-gitleaks-allow
```

如果当前版本支持，并且不会破坏必要的误报处理，则评估将其加入 CI 扫描命令。

不得未经验证直接修改参数。

需要确保：

- 工作树扫描仍然有效。
- 完整 Git 历史扫描仍然有效。
- 真实泄漏仍然能够触发 CI 失败。

## 3.3 强制验证

建立独立临时 Git 仓库，执行两种模拟泄漏测试：

**测试 A：工作树泄漏**

1. 创建模拟凭据。
2. 写入测试文件。
3. 执行工作树扫描。
4. 确认 Gitleaks 检测成功。
5. 确认退出码非 0。

**测试 B：历史提交泄漏**

1. 创建模拟凭据。
2. 提交至临时 Git 仓库。
3. 执行完整历史扫描。
4. 确认 Gitleaks 能发现历史泄漏。
5. 确认退出码非 0。

测试完成后清理临时仓库。

不得将模拟凭据写入真实项目 Git 历史。

# 四、任务二：补强全局网络隔离屏障

**优先级：P1**

涉及文件：

```
tests/network_guard.py
tests/test_network_guard.py
tests/run_tests.py
```

## 4.1 当前实现

目前已经覆盖：

```
socket.socket.connect
socket.getaddrinfo
socket.create_connection

http.client.HTTPConnection.connect
http.client.HTTPConnection.request
```

已经能够：

- 允许 IPv4 回环通信。
- 允许 localhost。
- 允许 IPv6 回环地址。
- 阻断公网 IP 连接。
- 阻断外部 DNS 解析。
- 阻断常见 urllib 外网请求。
- 允许本地 HTTP 测试服务。

但仍有其他网络入口需要检查。

## 4.2 补充网络拦截入口

重点审查以下接口：

### A. connect_ex

```
socket.socket.connect_ex()
```

要求：

- 本地回环连接允许。
- 外部 IP 连接必须在真正建立连接前阻断。
- 补充对应测试。
- 确认异常行为符合项目现有测试约定。

### B. UDP sendto

```
socket.socket.sendto()
```

要求：

- 允许向本地回环地址发送数据。
- 禁止向公网 IP 发送数据。
- 禁止通过外部 UDP DNS 等方式发送网络请求。
- 增加本地 UDP 通信测试。
- 增加外部 UDP 拦截测试。

### C. 其他 DNS 入口

重点检查：

```
socket.gethostbyname()
socket.gethostbyname_ex()
socket.getaddrinfo()
```

要求：

- 外部域名解析全部阻断。
- localhost 及允许的本地地址正常工作。
- 补充相应测试。

如果发现其他能够绕过现有屏障的 Python 标准库网络入口，也应评估是否需要覆盖。

不要为了追求接口数量而无差别 monkey patch。

## 4.3 修复本地地址白名单

当前代码包含：

```
if h in ("localhost", "127.0.0.1", "::1", "0.0.0.0", "::"):
```

这里需要修复。

`0.0.0.0` 和 `::` 属于通配地址，不应该作为允许的远程连接目标。

要求：

- 删除 `0.0.0.0`。
- 删除 `::`。
- 允许 IPv4 loopback。
- 允许 IPv6 loopback。
- 允许 localhost。
- 保留 Unix Domain Socket 本地通信。

统一使用明确的回环地址判定逻辑。

注意区分：

- 本地服务绑定地址。
- 客户端连接目标地址。

不要因为本地 HTTP 服务需要监听回环地址，就放宽外部连接白名单。

## 4.4 网络隔离测试补充

在原有 N01～N07 基础上增加测试。

建议编号：

| 编号 | 测试内容                  | 预期               |
| ---- | ------------------------- | ------------------ |
| N08  | connect_ex 连接本地地址   | 允许               |
| N09  | connect_ex 连接公网地址   | 阻断               |
| N10  | UDP sendto 发送本地数据   | 允许               |
| N11  | UDP sendto 发送公网数据   | 阻断               |
| N12  | gethostbyname 外部域名    | 阻断               |
| N13  | gethostbyname_ex 外部域名 | 阻断               |
| N14  | 通配地址白名单检查        | 不允许作为连接目标 |

可以根据实际实现合并或拆分测试，但必须覆盖上述行为。

另外，必须保证：

- 测试不依赖真实公网。
- 测试不执行真实 DNS 查询。
- 测试不依赖外部服务可用性。
- 本地 TCP/UDP 服务能够正常运行。
- 网络隔离屏障不会影响原有课表 Web API 测试。
