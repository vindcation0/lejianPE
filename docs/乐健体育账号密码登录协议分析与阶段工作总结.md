## 乐健体育账号密码登录协议分析与阶段工作总结

按照《乐健体育账号密码登录协议分析与命令行登录改造执行文档》中的规范与原则（“先研究、后验证、再实现；最小改动、保持兼容、不破坏现有认证和抢课系统”），本次阶段性逆向分析工作聚焦于 **官方 App（v3.10.3）完整登录链路的逆向拆解与算法破解**。

---

### 一、 核心逆向成果与技术突破

#### 1. 登录交互链路全景逆向
* **前端触发层（Uni-App）**：在 `captures/apk/assets/apps/__UNI__DEAC2C5/www/app-service.js`（`pages/login/index.vue`）中，用户点击登录后触发 `onClickLogin`，通过原生桥接 `uni.sendNativeEvent("loginRequest", { password, phone, baseUrl, authType })` 派发事件。
* **原生桥接与实体组装层（Java/Kotlin）**：在 `captures/apk/classes3.dex` 的 `UniAppActivity` 中接收并分发给 `UniAppViewModel.v`，解析为 `LoginReqBean` 实体：
  * 设置 `userName = phone`；
  * 组装待签名字符串：`toSign = userName + password + (entrance == null ? "" : entrance)`；
  * 调用 JNI 静态方法：`signDigital = cn.legym.ai.util.Rengis.hs(toSign)`；
  * 提交给 Retrofit 网络服务 `HttpUserApi.LoginByPwd(req)`。
* **真实网络端点与请求方式**：
  * **接口路由**：`POST https://cpes.legym.cn/authorization/user/v2/manage/login`（**注意：官方最新版为 v2 接口，历史文档记录的 v1 接口已被弃用**）。
  * **请求头**：`Content-Type: application/json`，且带有 `@SecurityAes` 注解。

#### 2. AES 动态信封加解密算法完全破解（已可纯 Python 实现）
通过深入逆向分析 `captures/apk/classes2.dex`（`SecurityRequestBodyConverter` / `SecurityResponseBodyConverter`）及底层 JNI 库 `captures/apk/lib/armeabi-v7a/libsecurity.so`（`getDynamicKey`），已完全破解乐健体育的动态加密信封协议：

* **外层信封结构**：
  ```json
  {
    "t": 1730438000000,
    "pyd": "<AES-128-ECB-PKCS5Padding 加密后的 Base64 字符串>"
  }
  ```
* **动态密钥派生算法 `getDynamicKey(t)`（纯 Python 还原）**：
  ```python
  def get_dynamic_key(t_str: str) -> bytes:
      """
      t_str: 13 位毫秒时间戳字符串，如 '1730438000000'
      """
      n1 = int(t_str[2:5])       # 如 '304' -> 304
      n2 = int(t_str[4:8])       # 如 '4380' -> 4380
      n3 = int(t_str[-1])        # 如 '0' -> 0
      shift = abs(n1 - n2) << n3 # abs(304 - 4380) << 0 = 4076
      hardcoded_secret = "402881ea7c39c5d5017c39d143a8062b"  # gitleaks:allow
      full_key = f"{shift}{hardcoded_secret}"
      return full_key[:16].encode("utf-8") # 截取前 16 字节作为 AES 密钥
  ```
* **加密模式**：`AES-128-ECB`，填充标准为 `PKCS5Padding`（等价于 `PKCS7Padding`）。
* **响应解密**：服务端返回同样的信封结构 `{"code":0, "data":{"t": ..., "pyd": "..."}}`，利用其携带的 `t` 重新派生密钥，对 `pyd` 进行 Base64 解码与 AES 解密即可得到明文 JSON。

### 三、 13.2 可行性结论

* **当前结论**：**部分可行，仍有阻碍**。
* **评估详情**：
  1. **已具备条件**：
     * 官方最新登录接口端点、请求信封结构、双向动态加解密密钥生成算法（`getDynamicKey`）已完全攻破并验证，纯 Python 环境无需额外依赖即可 100% 构造合法的请求报文并解密响应报文。
  2. **现存阻碍点**：
     * `signDigital` 字段由底层原生库 `libsportaction.so` 导出函数 `Java_cn_legym_ai_util_Rengis_hs` 生成。经深入分析，`libsportaction.so` 采用了顶象（Dingxiang Tech / DexVMP）加固保护，其代码段（0x48000~0x80000，包含 `ToHS` 与 `SHA1` 逻辑）在磁盘文件中被加密，运行时由 `libdexvmp.so` 动态解密。
     * 虽然从数据段中提取到了疑似硬编码盐值 `lgAI2021key~*21B`，且逆向到了 `SHA1` 类，但由于壳加密的存在，在纯静态分析下无法 100% 肯定 `SHA1` 是否拼接入该盐值或是否有其他硬件指纹入参。
     * 遵循文档严格的安全红线（“禁止猜测算法、禁止把猜想当成成功、未经验证不得修改核心模块”），在此阻碍完全排除前，**不应盲目集成至主程序 `menu.py` 或 `lejian.py` 中**。

### 五、 13.4 未解决问题与后续方向建议

1. **未解决事项**：
   * **`signDigital` 的确切哈希算法**：需要进一步确定 `ToHS` 是纯 `sha1(toSign)`、`sha1(toSign + "lgAI2021key~*21B")`，还是带有其它固定格式。
   * **设备指纹与风控验证码**：若触发风控，是否会要求顶象滑动验证码；若有滑动验证码，纯命令行环境需配合交互机制。
2. **后续建议步骤**：
   * **路径 A（优先）**：在模拟器中启动乐健体育 App 抓取一次真实的 `POST /authorization/user/v2/manage/login` 请求包（包含真实的 `userName`、`password` 与 `signDigital`），利用已破解的 AES 密钥解密，比对提取出的 `signDigital` 与 `sha1(toSign + salt)`，一旦匹配成功即可立即转为纯 Python CLI 登录。
   * **路径 B**：若抓包无法直接比对，可通过轻量级 Frida / Xposed 脚本 Hook `cn.legym.ai.util.Rengis.hs` 的输入与返回值，单次提取精确映射规则。
