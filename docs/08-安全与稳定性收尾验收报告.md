本阶段严格遵循「不增加新功能、不进行无关重构、不破坏现有抢课业务」的核心原则，对代码库进行了全面的安全排查、缺陷消除、异常增强与自动化测试补齐。

### 涉及修改的文件清单与修改内容：
1. **`tests/test_auth.py`**：
   - 清理所有测试用例中的真实或类真实数据（手机号、学号、signDigital 签名、Token UUID），全部替换为标准虚构占位测试数据（`13800138000`、`99999999`、`11112222...`、`aaaa...`）。
   - 补齐 A21～A32 全量测试用例（密码输入验证、日志防泄漏、DPAPI Fail-closed、账户隔离、写入异常保护、学期异常诊断等），新增针对 Windows DPAPI 的加密往返测试。
2. **`docs/07-命令行登录实现与验证报告.md`**：
   - 彻底脱敏文档中引用的真实 `schoolId`、`semesterId` 以及新签名字符串，全部替换为截断或脱敏标识。
3. **`core/credential_storage.py`**：
   - **消除了 DPAPI 加密失败时静默回退明文的安全漏洞**（Fail-closed 屏障）。若 DPAPI 加密异常，坚决拒绝保存并抛出 `CredentialError`，确保原有凭据完好无损。
   - Windows 环境默认启用 DPAPI 加密存储；非 Windows 环境显式拒绝 DPAPI 伪装。
   - 实现了落盘全流程临时文件校验：验证 `signDigitalEncrypted` 存在、明文 `signDigital` 彻底移除、以及密文往返解密一致性。
4. **`tools/login_cli.py`**：
   - 更新 `--setup` 在 Windows 下默认采用 DPAPI 加密保存。
   - 更新 `--encrypt` 命令：落盘后执行严格的二次解密回读核验，核验通过才报告成功。
5. **`core/auth_manager.py`**：
   - **修复跨账户状态污染漏洞**：重构 `save_state_atomically()`，将账户身份字段（`userId`、`realName`、`mobile`、`organizationUserNumber`、`campusId`）与旧会话彻底解耦。新账户登录仅写入自身身份信息，缺失字段严格置空，绝对不从旧账户会话中 fallback 继承！
   - **增强学期信息获取诊断**：重构 `fetch_semester_info()`，不再无条件吞掉异常，精准区分网络连接、HTTP 401、HTTP 500、业务状态错误等，并在无有效学期 ID 时抛出带明确诊断信息的 `SemesterInfoError`，强行保护原有 `state.json` 不被覆盖。
   - **事务性原子写入与备份保护**：完善临时文件写入、全字段验证与 `.bak` 备份回滚。
6. **`requirements.txt`**（新增）：
   - 声明生产与测试所需核心第三方依赖（`cryptography>=3.4.0`）。
7. **`.github/workflows/tests.yml`**（新增）：
   - 配置 GitHub Actions CI 多平台矩阵测试（Windows-latest + Ubuntu-latest，Python 3.10 / 3.11），支持 Push 与 PR 自动触发执行。

## 4. CI 验收与跨环境差异记录

项目已配置 GitHub Actions 持续集成工作流：
- **配置文件**：`.github/workflows/tests.yml`
- **触发机制**：推送代码至 `main` 分支或对 `main` 分支发起 Pull Request 时自动触发。
- **环境矩阵**：
  - `windows-latest` (Python 3.10, 3.11)
  - `ubuntu-latest` (Python 3.10, 3.11)

### 4.1 历史 CI 失败归因与环境差异（已记录并修复）
在初始工作流执行时，本地 Windows 环境与 GitHub Actions 虚拟运行环境表现出编码差异：
- **本地 Windows 11 环境**：默认控制台已在前期脚本配置了 UTF-8 支持，本地测试可正常输出日志。
- **GitHub Actions Windows Runner**：系统代码页默认为 `cp1252`，导致四个包含中文输出的测试用例失败：
  - `A16` (自动刷新 Token)：`lejian.py:73` 报 `UnicodeEncodeError: 'charmap' codec can't encode characters`
  - `A17` (RefreshToken 轮换)：`lejian.py:73` 报 `UnicodeEncodeError`
  - `T31` (分页请求异常)：`lejian.py:73` 报 `UnicodeEncodeError`
  - `T38` (旧版课表兼容)：`timetable/compatibility.py:37` 报 `UnicodeEncodeError`

### 4.2 针对性修复方案
1. **CI 运行环境变量注入**：在 `.github/workflows/tests.yml` 的测试任务与步骤中配置 `env: PYTHONIOENCODING: utf-8`，强制 Python 标准输出采用 UTF-8 编码。
2. **底层安全输出防护 (`_safe_print`)**：在 `lejian.py` 和 `timetable/compatibility.py` 的日志输出端增加编码容错处理，捕获 `UnicodeEncodeError` 并自动回退至终端编码字符替换模式（`errors='replace'`），彻底杜绝因控制台代码页不兼容导致程序或测试崩溃。
3. **敏感信息与密钥持续扫描**：在 CI 中引入 `gitleaks-action` 作为前置安全扫描任务。
