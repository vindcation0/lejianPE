## 0. 一句话结论

「乐健体育」是 uni-app 套壳应用，业务接口是 `https://cpes.legym.cn/` 上的普通 REST，
用 `Authorization: Bearer <token>` + `Organization: <schoolId>` 鉴权，**没有请求签名**。
因此不需要每次抓包，只要拿到 token 就能直接调用。

## 1. 目标与范围

学校体育课体系分两层：

| 层 | 内容 | 是否需要抢 |
|---|---|---|
| 体育主课程 | 一学年一门，如「趣味田径 周一14:00」，必修贯穿学期 | ❌ 已固定 |
| 课外活动 | 每周日 14:00 开放报名，每周限 2 节 | ✅ **本项目抢的是这个** |

课外活动入口在 App 底部【课外】tab，不是首页 banner，也不是「选课」模块。

**范围**：自动报名非会员制活动，并避开与真实课表的时间冲突。

## 3. 方法一：动态抓包（mitmproxy）

### 3.1 为什么 Android 15 特别麻烦

1. App 的 targetSdk 是 30（≥24），**默认不信任用户安装的 CA**
2. Android 14+ 把系统证书库搬进了 Conscrypt APEX：`/apex/com.android.conscrypt/cacerts`
3. `/system/etc/security/cacerts` 和上面那个 APEX 目录是**两份独立的只读拷贝**，都要覆盖
4. APEX 是独立 loop 挂载，**不随挂载传播**进已运行进程的命名空间

### 3.2 证书注入（可直接复用）

前提：`adb root` 成功；SELinux 为 Permissive（否则还要 `chcon`）。

```bash
# 1. 生成 CA（首次运行 mitmdump 会自动生成）
mitmdump --listen-port 18080      # 起来后 Ctrl+C 即可
#   产物在 %USERPROFILE%\.mitmproxy\

# 2. 推入设备
adb push mitmproxy-ca-cert.pem /data/local/tmp/mitm.pem

# 3. 构建暂存目录（保留原有 145 张证书，再追加自己的）
adb shell 'rm -rf /data/local/tmp/cacerts && mkdir -p /data/local/tmp/cacerts'
adb shell 'cp /apex/com.android.conscrypt/cacerts/* /data/local/tmp/cacerts/'
adb shell 'cp /data/local/tmp/mitm.pem /data/local/tmp/cacerts/c8750f0d.0'
adb shell 'chmod 644 /data/local/tmp/cacerts/*'

# 4. 用 tmpfs 覆盖两个只读目录
adb shell 'mount -t tmpfs tmpfs /apex/com.android.conscrypt/cacerts'
adb shell 'cp /data/local/tmp/cacerts/* /apex/com.android.conscrypt/cacerts/'
adb shell 'mount -t tmpfs tmpfs /system/etc/security/cacerts'
adb shell 'cp /data/local/tmp/cacerts/* /system/etc/security/cacerts/'

# 5. 关键：重启 zygote，让新进程继承 APEX 那个挂载
adb shell 'setprop ctl.restart zygote'
```

**第 5 步是整个流程的分水岭。** 不重启 zygote，App 进程里看到的还是原始 APEX 挂载，
TLS 握手会报 `client does not trust the proxy's certificate`。

### 3.3 文件名哈希

Android 用 `openssl x509 -subject_hash_old` 作为证书文件名。
mitmproxy 的 CA 主题固定为 `O=mitmproxy,CN=mitmproxy`，因此哈希恒为：

```
c8750f0d
```

（Windows 上通常没有 openssl，可用 `cryptography` 库对 `cert.subject.public_bytes()` 取 MD5 前 4 字节小端得到。）

> 补充：Android 的证书加载器会遍历目录解析每个文件，**不校验文件名是否等于哈希**，
> 所以文件名其实可以随便写。但保持规范没有坏处。

### 3.4 抓包链路

```bash
# 设备 8081 → 主机 8081（免去查 IP 和防火墙）
adb reverse tcp:8081 tcp:8081

# 设备走系统代理
adb shell 'settings put global http_proxy 127.0.0.1:8081'

# 主机起抓包
mitmdump --listen-port 8081 --set hardump=captures/lejian.har
```

清理：

```bash
adb shell 'settings put global http_proxy :0'
adb reverse --remove-all
```

### 3.5 抓包踩过的坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 只有 `www.mescroll.com` 能解密，legym 不行 | WebView 读 `/system`，OkHttp 读 APEX | 重启 zygote |
| `adb reverse` 莫名其妙失效 | adbd 重启会丢 | 每次重连后重新 `adb reverse` |
| `-w flows.mitm` 一直是 0 字节 | mitmproxy 的 `-w` 退出才落盘 | 改用 `--set hardump=` 或在跑完后退出 |
| 模拟器上【课外】【我的】tab 不显示 | MuMu WebView 渲染问题（推测） | 不影响，改走 API 直连 |

## 5. 接口清单

### 5.1 通用约定

```
Base URL : https://cpes.legym.cn/
Header   : Authorization: Bearer <accessToken>
           Organization: <schoolId>
           Content-Type: application/json
           User-Agent: okhttp/3.12.1
```

- 响应统一为 `{"code":0,"message":"成功","data":...}`
- `code != 0` 时 `message` 为中文原因
- **中文响应体是 GBK 编码**，不是 UTF-8（见坑 #2）

### 5.2 认证

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `authorization/user/manage/login` | 登录（无需 Authorization） |
| GET | `authorization/user/refreshToken?refreshToken=xxx` | 刷新（无需 Authorization） |
| GET | `authorization/user/getBasicInfo` | 用户信息 |

刷新响应：

```json
{"code":0,"data":{
  "accessToken":"...","tokenType":"bearer",
  "refreshToken":"...","accessTokenExpires":1792778769293
}}
```

**refreshToken 每次刷新都会轮换**，必须持久化最新的一个，否则下次刷新失败。

### 5.3 活动（本项目使用）

| 方法 | 路径 | 参数 |
|---|---|---|
| POST | `education/app/activity/getActivityList` | `{state, page, size, semesterId}` 或 `{state, page, size, day:7\|30}` |
| POST | `education/app/activity/my/getActivityList` | 我的活动 |
| GET | `education/app/activity/getStudentActivityDetail` | `?activityId=` |
| **POST** | **`education/app/activity/signUp`** | **`{activityId}`** ← 抢课 |
| POST | `education/app/activity/cancelSignUp` | `{activityId}` |
| **GET** | **`education/app/activity/checkConflict`** | **`?activityId=`** ← 服务端冲突检测 |
| GET | `education/activity/topic/list/for/activities` | 专题列表 |
| GET | `education/app/activity/signUpStatistics` | 报名统计 |
| POST | `education/activity/simple/attainability/get` | GPS 签到点 |
| PUT | `education/activity/app/attainability/sign` | 签到 |

**signUp 响应语义**（来自 `app_state` 判断逻辑）：

```json
{"code":0,"data":{"success":true}}
{"code":0,"data":{"success":false,"reason":"名额已满"}}
```

**checkConflict 返回值**：`data` 为真 → 存在冲突（App 会弹窗让用户确认）；为假 → 可直接报名。

> 注意：`state` 参数语义未完全确认。实测 `state=1` 返回「报名中」的全部活动。

### 5.4 学期

| 方法 | 路径 |
|---|---|
| GET | `education/semester/getCurrent` |

```json
{"code":0,"data":{
  "id":"8a97802f...","yearRange":"2026-2027",
  "startDate":1787673600000,"endDate":1801411199000,
  "index":1,"weekIndex":9
}}
```

`weekIndex` 与用户实际周次可能差一周，**不要盲信**，以教务系统为准。

## 7. 业务规则

### 7.1 已确认

| 规则 | 依据 |
|---|---|
| 抢的是【课外】活动 | 用户确认 |
| 每周最多 2 节 | 用户确认 + 实测第 3 次失败 |
| 每天最多 1 节 | 用户确认 |
| 体质健康测试不占上述名额 | 用户确认 |
| 会员制只是「口头约定」，非会员技术上也能报 | 用户实测 |
| 报名窗口由 `startRegisterTime` 决定 | 接口数据 |

### 7.2 实测观察

- 普通活动（足球/篮球/羽毛球…）名额 35–200，多数很快满员
- 会员制活动名额显示为 1，地址标注「需办会员手续」
- 某次快照中，25 个普通活动全部排在**周五**，周六周日只有会员制
- 普通活动报名窗口与活动同日，且**在活动开始前 2 分钟关闭**
- 会员制活动窗口比普通活动早数天开启（10-19 07:00 vs 10-18 14:00，非同一批）

### 7.3 推测（未验证）

- 每周日 14:00 开启的是**下一周**活动的报名窗口
- 一周内普通活动可能分布在多个日子，只是过期后从列表消失

> 这两条会直接影响「2 节必须落在两天」的判断，接手后请优先验证。

## 8. 踩过的坑（按严重程度）

### #1 名额统计未分周 → 周日必定空转

**现象**：周日跑起来一节都不抢。

**原因**：统计「已报几节」时算了所有 `isRegister`，上周的报名仍留在列表里，
于是误判「本周已满 2 节」。

**修复**：按活动所在教学周分别统计。

### #2 响应中文是 GBK

`urllib` 默认按 UTF-8 解码会得到 `�������ڲ�����`。
必须 `utf-8 → gbk → gb18030` 依次尝试。

### #3 APEX 证书挂载不传播

见 3.2 第 5 步。不重启 zygote 则抓不到乐健的流量。

### #4 课程名里有两个「周X」

`成都校区-趣味田径-2025-周天一-周一14:00~15:35`

用 `周([一二三四五六日])` 宽松匹配会先命中「周天」→ 误判成周日。

**修复**：把星期和时段绑成一个正则：

```python
re.compile(r"周([一二三四五六日天])\s*(\d{1,2}):(\d{2})\s*[~\-–—至]\s*(\d{1,2}):(\d{2})")
```

### #5 活动名带换行

`name` 实际是 `"户外跑\n程启航"`（教练名在第二行）。
直接打印会破坏排版，做子串匹配也可能出错。拉取时统一 `re.sub(r"\s+", " ", name)`。

### #6 已报名活动不占时段

只跳过 `isRegister` 的那一条，**它占用的时间没有进冲突表**，
导致同一时段另一老师的班会被误判为可抢。

**修复**：把已报名活动的 `(week, slot)` 也并入占用表。

### #7 bat 文件不能写中文

中文版 Windows 的 cmd 按 GBK 解析 .bat，UTF-8 中文会把字节打散，
连 `errorlevel` 都会变成 `rrorlevel` 报错。

**修复**：`.bat` 只用 ASCII，中文菜单放进 Python（UTF-8 + `chcp 65001`）。

### #8 模拟器渲染缺 tab

MuMu 上底部只显示【首页】【课程】，【课外】【我的】不渲染（推测是 WebView 合成问题）。
不影响本项目，因为直接走 HTTP，不点按钮。

## 9. 代码结构

```
lejian.py                    主程序
├─ Client                    鉴权 + 请求 + token 自动续期
├─ activities()              分页拉活动
├─ check_conflict()/sign_up() 报名相关
├─ parse_slot / overlaps     时段解析与重叠判定
├─ week_of()                 绝对锚点换算教学周
├─ busy_for_week()           某周占用时段（课表 + 手填 + 本次已抢）
├─ pick_targets()            规则过滤（会员/冲突/名额/每天上限/志愿匹配）
└─ cmd_*                     五个子命令

config.json     抢课规则
timetable.json  课表（week1_monday 锚点 + 带周次的课程）
state.json      凭据（已 gitignore）
```

### 教学周换算

不按「今天所在周一」推算（换个日期跑就会错），而是存**第 1 周周一**的绝对日期：

```
week1_monday = 本周一 - 7 × (current_week - 1)
week(date)   = (date - week1_monday) // 7 + 1
```

### 规则执行顺序

```
拉列表
 → 排除 isRegister / 会员制 / 满员 / 无时间
 → 按活动自身周次取占用表，排除时间冲突
 → 排除当天已达上限的
 → 按 targets 顺序匹配，取第一个命中的
 → checkConflict（服务端兜底）→ signUp
```

## 10. 复现 / App 更新后怎么办

### 只改前端、接口没变

一般不用动。活动列表结构比较稳定（`data.items[]`），若字段改名，
只需要调整 `lejian.py` 里 `Client.activities()` 的解析和 `pick_targets()` 的字段名。

### 接口变了

1. 重新抓包（第 3 节），或在模拟器里 `adb pull` 新的 APK
2. 解包 → 打开 `assets/apps/__UNI__*/www/app-service.js`
3. 搜 `education/` 前缀关键字，定位新的路径与参数
4. 用 `tools/api_test.py` 这类脚本先裸调验证，再改 `lejian.py`

### 换学期

1. 重新导出课表 md → `python tools\build_timetable.py "路径" <当前周>`
2. 改 `config.json` 的 `current_week`
3. `[9]` 重新同步 token

## 12. 合规与风险

- 本项目**只操作本人账号**，不涉及多账号、代抢、倒卖
- 会员制活动在接口层无任何校验，排除它们纯粹出于**约定与公平**，不是技术限制
- 学校若认定脚本选课违规，最重可取消选课结果
- `state.json` 含真实姓名、学号、手机号与 token，**绝不可提交或外传**
- token 泄漏的止损方式：在 App 内重新登录，旧 refreshToken 即刻作废

## 13. 实战记录：2026-10-25 首战

> 完整的故障记录、证据与根因分析见：[05-2026-10-25-故障报告](05-2026-10-25-故障报告.md)

**结果**：抢到 2 节（周三、周五 17:40 户外跑），达成目标。中间多拿了 1 节，已退掉。

### 时间线

| 时刻 | 现象 |
|---|---|
| 14:00:00 | 全校同时请求，接口开始返回 HTTP 500 |
| 14:00–14:01 | 500 密集且偶发，单次轮询从 0.5s 退化到 15s 超时 |
| 14:01:41 | 首次成功，`total` 从 116 → 144，新批次已在 |
| 14:03–14:06 | 列表可间歇拉取，`signUp` 全部 502 / 503 |
| 14:06 | 收到「该类型活动已达到每周上限」→ 反证有提交其实已成功 |
| 14:14 | 复核发现实际落了 **3 条**，退掉 1 条，恢复为 2 条 |

### 四条教训

1. **503 不代表失败。** 网关报错时请求可能已被后端处理。
   必须用 `isRegister` 复核真实状态，不能只看响应码。
2. **超时要短。** 15s 超时让一次轮询白等，两分钟只轮询了 20 次；
   改成 5–6s 后重试密度提升约一个数量级。
3. **绝不并发多进程。** 两个进程同时提交会绕过服务端计数校验，
   直接突破每周上限（本次就多拿了一节）。
4. **名额上限不是原子操作。** 并发下服务器会放行超额请求，
   事后必须复核并退课修正。

### 下次的处置预案

- 14:00 前完成 token 与课表确认
- **只跑一个进程**
- 提交失败后，每 3–5 秒用 `isRegister` 复核一次，再决定是否重试
- 抢满后立即复核；若超限，马上退掉多余的一条
