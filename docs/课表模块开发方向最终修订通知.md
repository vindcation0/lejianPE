# 课表模块开发方向最终修订通知

## 一、最终产品决策

经过需求调整，项目不再开发原定的多格式课表导入系统。

取消以下功能：

- Markdown 课表导入。
- PDF 课表导入。
- PNG/JPG 图片识别。
- OCR 文字识别。
- AI 自动识别课表。
- Excel、Word 课表导入。

不再投入精力开发不同学校的课表文件解析器。

本项目统一采用：

**本地 HTML 可视化课表编辑器。**

用户通过浏览器中的星期 × 时间表格，直接勾选自己有课的时间段。

最终由 Python 接收结构化数据，校验后生成统一的 `timetable.json`。

## 二、核心功能

### 1. 本地页面启动

用户在命令行选择可视化编辑课表后：

1. Python 启动本地 HTTP 服务。
2. 服务仅监听 `127.0.0.1`。
3. 自动打开默认浏览器。
4. 用户在 HTML 页面中编辑课表。
5. 用户确认后，JavaScript 通过本地 HTTP 接口向 Python 提交 JSON。
6. Python 校验数据并保存。

不需要前端框架，不引入 React、Vue 等额外依赖。

优先使用 HTML、CSS、原生 JavaScript 和 Python 标准库实现。

### 2. 课表编辑界面

采用二维表格布局：

- 横向：星期一至星期日。
- 纵向：用户自定义时间段。
- 单元格：表示该星期、该时间段是否有课。

交互要求：

- 点击空白单元格：标记有课。
- 再次点击：取消有课。
- 有课和空闲状态有明显视觉区别。
- 支持批量选择和清空。
- 支持编辑已有课表。

### 3. 时间配置

时间轴必须允许用户自由配置。

支持：

- 修改开始时间。
- 修改结束时间。
- 新增时间段。
- 删除时间段。
- 不同时间段可以具有不同的时长。

不能将 45 分钟或 90 分钟写死。

时间行只是用户的选择单位，最终保存具体的开始和结束时间。

### 4. 教学周设置

支持：

- 每周。
- 单周。
- 双周。
- 自定义周次。

用户切换周次模式时，之前已经勾选的内容必须保留。

例如：

- 周一 08:00-09:35：单周有课。
- 周二 08:00-09:35：双周有课。
- 周三 14:00-15:35：第 1、3、5、7 周有课。

最终全部转换为统一的 weeks 区间。

需要设置：

- 第一教学周周一日期。
- 总教学周数。

### 5. 统一数据结构

最终只生成：

```
{
  "schema_version": 2,
  "week1_monday": "2026-08-31",
  "busy_slots": [
    {
      "weekday": 1,
      "start": "08:00",
      "end": "09:35",
      "weeks": [[1, 16]]
    }
  ]
}
```

字段说明：

- weekday：星期，1-7。
- start：开始时间。
- end：结束时间。
- weeks：有效教学周次。

不需要课程名称、教师、教室等信息。

### 6. 保存与校验

点击确认后：

1. 页面展示最终时间占用信息。
2. 检查时间格式。
3. 检查开始时间是否早于结束时间。
4. 检查星期范围。
5. 检查周次范围。
6. 检查是否存在重复记录。
7. 校验通过后备份旧文件。
8. 使用原子写入方式生成新版 `timetable.json`。

保存失败不能破坏已有课表。

### 7. 已有课表编辑

如果本地已经存在 `timetable.json`：

- 自动读取。
- 自动填充星期和时间网格。
- 恢复原有周次选择。
- 用户可以继续编辑。
- 确认后保存更新。

必须保留旧版 courses 数据迁移能力，避免现有用户的课表直接失效。

## 三、技术实现约束

1. Python 负责本地服务和数据保存。
2. HTML 负责页面布局。
3. CSS 负责视觉效果。
4. JavaScript 负责交互和状态管理。
5. JSON 作为前后端通信格式。
6. 不依赖云服务。
7. 不上传用户课表。
8. 本地 HTTP 服务只能监听 127.0.0.1。
9. 保存接口需要校验请求来源或使用本次运行的随机会话令牌。
10. 页面关闭后应正常停止临时服务或提供明确的退出机制。

## 四、实施顺序

第一阶段：

- 完成 HTML 页面。
- 完成星期 × 时间网格。
- 完成单元格勾选。
- 完成时间段编辑。

第二阶段：

- 完成单双周。
- 完成自定义周次。
- 完成教学周日期配置。

第三阶段：

- 完成 Python 本地服务。
- 完成 JSON 提交。
- 完成数据校验与保存。

第四阶段：

- 支持已有课表加载和编辑。
- 完成旧版数据迁移。
- 完成自动化测试。
- 更新 README。

## 五、验收要求

- 

  页面能够从命令行正常启动。

- 

  浏览器能够自动打开。

- 

  可以选择星期和时间。

- 

  可以自定义时间段。

- 

  可以设置每周、单周、双周。

- 

  可以设置自定义周次。

- 

  切换周次模式不会丢失之前的选择。

- 

  能够正确生成 busy_slots。

- 

  能够读取并编辑已有课表。

- 

  旧版数据可以安全迁移。

- 

  保存失败不会破坏旧课表。

- 

  现有抢课冲突判断逻辑保持正确。

- 

  原有抢课业务规则不受影响。

## 六、明确禁止扩大任务范围

本次只实现可视化时间占用编辑器。

不允许重新引入：

- Markdown 导入。
- PDF 导入。
- OCR。
- AI 识别。
- 多格式解析器。

不要为了所谓的扩展性引入复杂架构。

优先保证界面好用、数据正确、保存可靠、与现有抢课程序兼容。

**最终目标：让用户只需要在浏览器中点击自己有课的时间，就能完成课表配置。**
