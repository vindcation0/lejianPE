# Phase 8：实战数据闭环与发布验收修复

第四轮优化 Phase 0–7 已完成。

历史测试结果：

- 单元测试：440 PASS
- 集成测试：80 PASS
- 总计：520/520 PASS

但 2026-11-08 实际抢课暴露了审计报告统计错误：

| 指标         | 实际 | 自动报告 |
| ------------ | ---- | -------- |
| 活动列表失败 | 18   | 0        |
| 故障中断时间 | 存在 | 0        |

| 最终报名     | 2    | 2        |

本阶段目标不是重构核心架构，而是修复真实运行数据与报告之间的不一致。

## 二、P0：审计统计修复

重点文件：

- core/audit_logger.py
- core/result_reporter.py
- lejian.py

任务：

1. 统一 list_fault_started、list_fail 等事件的统计语义。
2. 修复 AuditLogReader.replay 对活动列表故障事件的识别。
3. 修复 infrastructure_recovered 的故障时长统计。
4. 检查 set_circuit_metrics 是否覆盖 AuditLogReader 已经计算的统计结果。
5. 分开统计 activities 与 checkConflict 的失败。
6. 分开统计 Submission 与 Verification。
7. 修复真实提交次数统计不一致的问题。
8. 保留历史事件格式兼容性。

要求：

- 原始 JSONL 是运行事件的事实来源。
- 同一事件不能重复计数。
- run_id 必须严格匹配。
- 不得将复核请求统计为报名提交。
- 不得将 HTTP 失败次数等同于熔断次数。

## 三、P1：真实事件回放测试

建立 2026-11-08 真实故障序列的脱敏测试样本。

必须覆盖：

1. 连续列表请求失败。
2. 不同 HTTP 状态码。
3. 多次服务恢复。
4. UNKNOWN 产生。
5. UNKNOWN 复核成功。
6. UNKNOWN 复核失败。
7. 多个候选依次提交。
8. 最终全局对账。
9. 报名成功和未决状态。
10. 同一事件重复读取。

验证最终报告与已知实际数据一致。
