## 二、M0 阶段：现有认证代码梳理与复用策略

### 2.1 现有核心模块职责与能力盘点

1. **`core/auth_error.py`**：
   - 包含面向异常类型的继承树：`AuthError`、`CredentialError`、`InvalidCredentialError`、`BusinessAuthError`、`TokenAcquisitionError`、`SchoolInfoError`、`SemesterInfoError`、`AuthNetworkError`。
   - **复用决策**：保持既有异常类定义 100% 向后兼容，作为错误诊断器的输入来源。

2. **`core/credential_storage.py`**：
   - 负责凭据 `credential.json` 的存储与加载。
   - 包含 Windows DPAPI 加解密、Fail-closed 安全屏障、原子替换、以及脱敏工具 `mask_account` 与 `mask_secret`。
   - **复用决策**：直接复用其加解密逻辑和基础脱敏能力。

3. **`core/auth_manager.py`**：
   - 负责 AES-128-CBC 信封打包与发送、HTTP 状态与业务码解析、学期拉取及 `state.json` 原子保存。
   - **复用决策**：保持 `login()` 与 `save_state_atomically()` 的业务与校验逻辑不变，由上层捕获异常后统一接入诊断器。

4. **`tools/login_envelope.py`**：
   - 负责 AES 登录信封的 `wrap` 与 `unwrap`。
   - **复用决策**：完全复用，不做修改。

5. **`tools/capture_login.py`**：
   - 负责与 Android 模拟器通信、注入证书、透明代理抓包与签名提取。
   - **复用决策**：保持独立可用，为后续 M2 一键重新初始化提供基础。

6. **`tools/login_cli.py`**：
   - 命令行密码登录入口。
   - **改动范围**：接入 `handle_login_failure`，在凭据加载、登录认证、会话落地出错时统一输出诊断报告。

## 三、M1 阶段：登录失败自动诊断系统设计与实现

### 3.1 统一错误分类映射矩阵

在 `core/auth_diagnostics.py` 中实现了 `ErrorCategory` 与 `diagnose_auth_error()`，完整覆盖计划要求的 12 种典型场景：

| 错误分类 (`ErrorCategory`) | 判断依据 / 触发源 | 用户提示摘要 | 建议操作 | 是否可重新初始化 (`can_reinit`) |
| :--- | :--- | :--- | :--- | :---: |
| **`SIGNATURE_ERROR`** | 服务端业务码 `50004` 或包含签名校验失败 | 客户端提供的登录签名 (signDigital) 校验失败 | 引导重新初始化认证凭据（主菜单 `[b]`） | **是** |
| **`WRONG_PASSWORD`** | 明确包含密码错误、账号错误或业务码 10001/10002 | 账号或密码不正确 | 核对账号密码，重新输入 | 否 |
| **`TOKEN_EXPIRED`** | HTTP 401 或服务端明确 Token 过期 | 登录会话已过期或已被服务端作废 | 重新执行命令行登录获取新 Token | 否 |
| **`REFRESH_TOKEN_EXPIRED`** | 刷新接口拒绝或 RefreshToken 过期 | 长期刷新凭据失效，无法自动刷新 | 重新执行账号密码登录 | 否 |
| **`NETWORK_ERROR`** | DNS 失败、连接超时 (TimeoutError)、断网 | 无法建立与乐健服务器的网络通信连接 | 检查本地网络与系统代理设置后重试 | 否 |
| **`SERVER_ERROR`** | HTTP 500 / 502 / 503 / 504 服务端故障 | 乐健服务端基础设施出现异常 (HTTP 5xx) | 服务端维护中，建议稍后重试 | 否 |
| **`CLIENT_PARAM_ERROR`** | HTTP 429 限流保护或 HTTP 4xx 请求参数有误 | 登录请求过于频繁触发限流，或参数非法 | 暂停操作等待 1~3 分钟后再试 | 否 |
| **`DECRYPT_FAILED`** | AES 登录信封 (pyd) 解密失败 | 服务端返回的加密载荷解密失败 | 检查本地北京时间同步，保存报告反馈 | 否 |
| **`MALFORMED_RESPONSE`** | 缺少必要字段 (`accessToken`/`schoolId`/`data`) | 服务端响应格式非法或缺失必要字段 | 系统已阻止残损会话落地，保护原会话 | 否 |
| **`CREDENTIAL_CORRUPTED`** | 本地 `credential.json` 缺失、非合法 JSON 或缺少必要字段 | 本地认证凭据缺失、损坏或不完整 | 引导重新执行初始化生成凭据 | **是** |
| **`DPAPI_UNAVAILABLE`** | 非 Windows 环境或 DPAPI 解密失败 | Windows DPAPI 凭据安全加解密异常 | 重新初始化或非 Windows 下切明文模式 | **是** |
| **`UNKNOWN_ERROR`** | 无法归类的未知非标异常 | 登录过程遇到未分类的未知异常 | 提供脱敏诊断报告与原因待排查提示 | **是** |

> **关键设计原则**：对于 `50004` 签名错误，系统**不武断断定一定是用户修改了密码**，而是客观指出可能为：① 在 App 端修改过密码；② 本地凭据签名失效；③ 客户端入口参数变动。

### 3.2 终端输出格式规范

输出的人类可读诊断报告严格遵循统一规范：

```text
==================================================
                ========== 登录诊断 ==========
==================================================
诊断编号：DIAG-AUTH-20261101140000-1234
诊断时间：2026-11-01 14:00:00
登录结果：失败
操作账号：138****8000
错误类型：认证签名错误 (50004)
服务端响应代码：业务代码 50004, HTTP 200

问题摘要：服务端拒绝认证请求：客户端提供的登录签名 (signDigital) 校验失败。

可能原因：
  1. 账号在官方 App 端曾修改过密码（导致签名绑定的密码哈希失效）。
  2. 本地 credential.json 中保存的 signDigital 已经失效或过期。
  3. 客户端登录入口 (entrance) 或认证上下文参数发生变更。

建议操作：
  1. 重新初始化认证凭据：使用主菜单 [b] 重新抓取登录签名。
  2. 若曾在 App 端修改过密码，请确保在重新抓包时使用最新密码登录。
==================================================
```

### 3.3 安全脱敏保证

实现了专门的 `mask_sensitive_text()`，确保在任何错误信息和终端输出中：
1. **密码**：绝不打印密码明文，正则替换为 `[PROTECTED]`。
2. **Token**：严格屏蔽 Bearer JWT 及长散列字符串为 `[MASKED_TOKEN]`。
3. **signDigital**：对签名 Hex 字符串或 DPAPI 密文替换为 `[MASKED_SIGNATURE]` / `[MASKED_CIPHERTEXT]`。
4. **账号**：统一通过 `mask_account()` 保留前 3 后 4 位。

### 3.4 交互与非交互友好性

`handle_login_failure` 自动识别运行环境：
- **非交互式（如测试或后台调度）**：输出诊断报告并立即返回，保证退出码为 1，不阻塞进程。
- **交互式终端**：输出诊断报告后提供清晰选项：
  - `[1] 开始重新初始化认证凭据`（在 M1 提示可通过主菜单 `[b]` 执行，为 M2 预留回调）
  - `[2] 返回主菜单/退出`
  - `[3] 查看详细诊断信息（已脱敏）`
