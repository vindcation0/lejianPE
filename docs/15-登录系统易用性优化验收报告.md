## 二、M2 阶段：一键重新初始化架构与六步生命周期实现

在 `core/auth_initializer.py` 中实现了 `AuthInitializer` 统一管理类，将分散在抓包、解析、验证与落盘的流程编排为严格的事务性链路：

        └─────────────────────────────────┘

        └─────────────────────────────────┘

        └─────────────────────────────────┘
                         │
                         ▼

        │ 步骤 4：严格预校验新凭据         │

### 2.1 核心步骤与安全机制设计

1. **步骤一：检查当前认证状态 (`check_status`)**：
   - 只读核查 `credential.json`（是否存在、是否 DPAPI 受保护、是否能正常解密）与 `state.json`（Token 是否过期、学期与学校代码）。
   - 严格脱敏输出，绝不向终端或日志展示明文密钥与签名材料。

2. **步骤二：准备官方客户端提示 (`prompt_client_preparation`)**：
   - 明确提示用户确认模拟器已 Root、启动乐健体育 App；
   - 明确标出当前绑定的操作账号（掩码格式），告知用户**必须在 App 中使用该账号登录**，系统会自动执行账号一致性校验。
   - 申明三项安全原则：不绕过官方协议、绝不保存明文密码、验证完全通过后才原子替换。

3. **步骤三：从抓包日志提取认证材料 (`extract_from_flows`)**：
   - 复用现有 `login_envelope.unwrap` 与抓包日志解析逻辑，提取 `account`, `signDigital`, `entrance`。
   - 若未检索到成功的登录记录，抛出 `InvalidCredentialError`，友好提示用户检查 App 登录操作。

4. **步骤四：严格验证新凭据 (`verify_new_credential`)**：
   - **账号一致性强校验（防串号污染）**：若本地已有配置账号，核验采集到的账号是否完全一致。如果用户在模拟器中误登了他人的账号，立即触发安全拦截，抛出明确错误并拒绝采纳，**杜绝误用他人账号污染本地配置**！
   - **在线真实登录核验**：调用 `AuthManager.login` 发起请求，确保新签名的有效性。若返回 50004、密码错误、网络超时或缺少 Token，立即拦截。
   - **只有校验全部通过，才允许进入落盘替换阶段**。

5. **步骤五：原子替换旧凭据 (`apply_new_credential_atomically`)**：
   - 复用 `CredentialStorage.save_credential`，写入 `.tmp` 临时文件；
   - 执行回读校验与 Windows DPAPI 往返解密比对；
   - 自动生成 `.bak` 备份文件；
   - 校验通过后通过 `os.replace` 原子替换原文件。若写入或加密失败，原有凭据毫发无损。

6. **步骤六：拉取学期并更新会话 (`update_session_atomically`)**：
   - 验证成功后通过 `AuthManager.save_state_atomically` 拉取当前学期，以事务方式原子更新 `state.json`，确保原有字段结构与 Token 刷新机制完全兼容。

## 三、统一入口集成协同

为方便用户在各个场景下无缝发起重新初始化，M2 提供了四大统一入口调用：
1. **主菜单集成**：`menu.py` 中的 `[b]` 项更新为 `重新初始化认证（一键修复凭据与会话）`，直接调用 `lejian.py reinit`。
2. **命令行入口**：`lejian.py` 新增 `reinit` 子命令，支持直接在终端运行 `python lejian.py reinit`。
3. **登录失败诊断自动引导**：`core/auth_diagnostics.py` 的 `handle_login_failure` 在用户选择 `[1] 是，开始重新初始化认证凭据` 时，直接触发 `AuthInitializer().reinitialize()`。
4. **底层独立工具保持兼容**：原有的 `tools/capture_login.py` 继续保留独立运行能力，不破坏既有运维习惯。
