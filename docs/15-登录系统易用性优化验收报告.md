## 二、M3 阶段：首次配置向导与 7 类用户状态智能处理矩阵

首次配置向导绝非简单的“静态欢迎页”，而是一个具有完整环境自检、状态嗅探与智能分流的决策自愈引擎。系统在 `core/config_wizard.py` 中实现了 `ConfigWizard`，全面识别并精准处理 7 类用户启动状态：

### 2.1 用户状态与向导处理矩阵

| # | 用户当前状态 | 探测依据 | 向导处理策略与路径 | 优势与用户价值 |
| :-: | :--- | :--- | :--- | :--- |
| **1** | **完全没有配置 (`NO_CONFIG`)** | `credential.json` 与 `state.json` 均不存在 | 启动从头引导：环境自检 -> 引导启动模拟器与官方 App -> 输入账号密码 -> 调用抓包采集签名 -> 在线验证 -> WAL 复合事务原子写入生成凭据与会话 | 零基础新用户按照控制台指引一步一步完成开箱配置 |
| **2** | **有凭据，没有会话 (`CRED_WITHOUT_STATE`)** | `credential.json` 有效且可解密，但缺失有效 `state.json` | **免抓包快速登录**：直接提示已绑定的脱敏账号，仅需用户输入密码，使用已有 `signDigital` 完成登录并拉取学期生成 `state.json` | **彻底免去繁琐的模拟器抓包流程**，2 秒内迅速补齐会话 |
| **3** | **已有有效凭据和会话 (`READY`)** | `credential.json` 正常且 `state.json` 中 Token 仍未过期 | **跳过初始化**：展示当前绑定账号、学校代码、学期与剩余有效期，提示环境已健康就绪，直接返回成功放行进入主程序 | 避免对正常用户产生不必要的弹窗与重复配置干扰 |
| **4** | **凭据损坏或无法解密 (`CRED_CORRUPTED`)** | `credential.json` 损坏、格式非法或 DPAPI 解密失败 | 明确给出凭据损坏原因，友好询问是否重新抓包修复，确认后直接调起 `AuthInitializer.reinitialize()` | 避免抛出原始 Python Traceback，明确引导修复路径 |
| **5** | **Token 过期但 RefreshToken 有效 (`TOKEN_EXPIRED_REFRESHABLE`)** | `accessToken` 已过期，但 `state.json` 存在有效 `refreshToken` | **优先静默自动刷新**：向导主动调用服务端刷新接口尝试静默延长 Token；若刷新成功，原子更新 `state.json` 并直接转为 `READY` 就绪状态 | 用户感知不到过期，无需重新输入密码即可无缝继续使用 |
| **6** | **会话失效或刷新被拒 (`SESSION_EXPIRED`)** | 缺失 RefreshToken 或静默刷新被服务端拒绝 (401) | **平滑降级免抓包登录**：提示会话已失效，利用本地完好的凭据引导用户输入密码重新登录更新会话 | 即使 Token 彻底过期，也无需重新打开模拟器抓包 |
| **7** | **上次初始化中途退出 (`PENDING_TRANSACTION`)** | 磁盘残留未标记 `COMMITTED` 的事务日志 (`*.tx.json`) | **开机自愈守护**：向导优先调用 `recover_pending_transaction()`，自动将凭据与会话回滚恢复至事务开始前的干净一致状态，随后重新评估状态继续引导 | 彻底防御断电、强杀进程带来的配置撕裂隐患 |

## 三、针对 M3 的 4 项核心深度加固设计

为追求极高的工程严谨性与鲁棒性，在 M3 基础向导之上进一步实施了四项关键加固：

### 3.1 快速登录失败后的闭环重初始化 (P0)
- **业务场景**：用户在乐健官方 App 或 Web 端修改了密码，本地保存的旧 `signDigital` 随之作废。此时如果执行快速登录，服务端将返回业务码 50004（签名校验失败）。
- **防御死循环**：若系统此时机械地提示“密码错误，请重新输入”，用户将陷入反复输密码的死胡同。
- **加固实现**：在 `quick_login_with_existing_credential` 中，登录异常被捕获后通过 `diagnose_auth_error` 分流：
  - 若为 `SIGNATURE_ERROR`（`diag.can_reinit == True`）：明确告知用户“检测到签名失效（可能因近期修改密码或官方凭据作废），继续输入密码无法登录”，并主动询问是否立即调用 `AuthInitializer.reinitialize()` 重新抓包采集；
  - 若用户确认，直接无缝衔接初始化流程；若取消，干净退出。
  - 若为 `WRONG_PASSWORD`：提示检查密码；若为 `NETWORK_ERROR`：提示检查网络连接。

### 3.2 静默刷新防并发冲突 (Single-flight) 与 10 秒失败冷却保护 (P1)
- **并发与轮换风险**：在多线程或并发请求场景下，多个任务同时发现 `accessToken` 过期时，若同时向服务端发起刷新请求，后到达的请求将因服务端 RefreshToken 轮换机制（已作废旧 RefreshToken）被判 401 失败。
- **Single-flight 单飞设计**：
  - 引入模块级类锁 `_refresh_lock = threading.Lock()`；
  - 采用 **Double-Checked Locking（双重检查锁）**：获得锁后再次检查磁盘上的 `accessTokenExpires`，若其他线程已完成刷新且 Token 仍有效，直接复用已更新的 Token，不再穿透调用服务端网络接口；
  - 严格确保全局同一时刻仅有 1 个请求穿透向服务端发起刷新。
- **10 秒失败冷却保护 (`_last_refresh_fail_time`)**：
  - 若刷新接口因网络或权限失败，记录失败时间戳；
  - 在 10 秒冷却期内再次收到刷新请求时，直接触发降级分流，不重复敲打服务端，杜绝无限死循环重试加剧服务端压力。

### 3.3 密码内存安全与客观生命周期管理
- **客观技术表述**：Python 中的 `str` 是不可变对象，且受 CPython 小字符串驻留与 GC 分代回收控制。使用 `del password` 仅解除了局部变量引用，无法物理清零内存中的字节。
- **安全加固落地**：
  - 文档与代码停止承诺“物理安全擦除”；
  - 严格落实业界标准防泄露规范：交互时使用 `getpass.getpass()` 终端不回显；全程禁止打印至日志（`[FILTERED]`）与持久化至文件；局部变量即用即注销，尽最大努力缩短密码在内存中的存活窗口。

### 3.4 6 维环境自检与非阻断式网络探测
- **自检维度**：
  1. **Python 版本**：要求 `>= 3.8`；
  2. **平台与加密支持**：检测 Windows DPAPI（硬件级加密）或 POSIX 权限加固；
  3. **关键工作目录写权限**：验证 `data/`、`logs/`、`captures/` 及根目录的写权限；
  4. **SQLite 驱动**：内存建表验证数据库驱动就绪；
  5. **安卓 ADB 工具探测**：探测 `adb` 是否在 PATH 中（非阻断项）；
  6. **网络连通性探测**：探测官方接口 `cpes.legym.cn` 的可达性（非阻断设计）。
- **非阻断式离线可用**：
  - 抢课程序具备大量离线查看功能（如查看本地保存的课表 `python lejian.py timetable`、可视化排课编辑等）；
  - 当离线或弱网探测失败时，自检结果将其标记为 `WARNING`，但 `overall_ok` 仍保持 `True`，确保在无网环境下依然放行用户的本地操作。

## 六、M4 阶段：独立系统体检与非破坏性只读诊断 (System Doctor)

为了实现长期免维护、用户自助排查与生产环境无侵入体检，M4 在 `core/system_doctor.py` 中实现了 `SystemDoctor`。

### 6.1 核心设计与非破坏性约束
1. **非破坏性只读诊断（Non-destructive Diagnostics）**：
   - **严格业务数据零写入**：绝不修改任何用户业务配置文件（`config.json`, `timetable.json`）；绝不修改、覆盖或删除任何凭据与会话文件；绝不修改或重置 SQLite 数据库；绝不触发任何报名、选课或修改操作。
   - **SQLite 只读连接**：数据库连接明确采用 `file:...mode=ro` URI 只读模式，底层杜绝产生数据库写事务或修改 WAL 文件。
   - **临时探测文件受控生命周期**：仅在目录权限探测时创建 `.doctor_probe_*.tmp`，在 `finally` 块中立即 `unlink` 清除；且在诊断开始前自动扫描清理可能因系统断电遗留的历史探测文件。
   - **网络外部副作用客观说明**：在线验真过程只读查询当前学期，虽然不修改本地状态，但会向服务端发起 HTTP 请求，产生服务端网络访问日志与限流配额消耗。
2. **凭据安全与保护机制客观表述**：
   - **Windows 平台**：采用 **Windows DPAPI 凭据安全保护**（基于 Windows 用户安全上下文的加密保护机制，不夸大为硬件级加密）；
   - **POSIX 平台**：采用受限文件权限保护（`chmod 0600`，属于系统级文件访问控制，明确区分于密码学密文加密）；
   - **平台不支持安全存储时**：坚持 Fail-closed 策略，拒绝静默降级为明文存储。
3. **在线 Token 验真 401 细分处理**：
   - 不再将所有 HTTP 401 机械断言为 Token 作废；
   - 细分区分：HTTP 401 响应体、服务端业务错误码、明确过期、明确撤销与未授权响应；
   - 仅在服务端响应体明确指出 `expired` 或 `revoked` 时，断言 Token 失效；
   - 对于通用 401 未授权响应，客观报告“服务端返回 HTTP 401 未授权响应（具体原因暂时无法确定）”，并给出重检会话建议。
4. **全流程严格安全脱敏**：
   - 不输出明文密码；账号自动脱敏（如 `186****7060`）；签名只展示前 4 后 4 及总长度；Token/RefreshToken 掩码展示；绝不泄露 AES 密钥。
3. **分级评估模型**：
   - **`HEALTHY (正常)`**：所有核心环境、配置、凭据、会话、在线服务均就绪；
   - **`WARNING (警告)`**：系统基础功能可用，但存在待优化项（如 Token 已过期但可刷新、未配置 ADB、离线受阻）；
   - **`ERROR (异常)`**：存在阻断性故障（如 Python < 3.8、目录不可写、凭据损坏、数据库完整性损坏、Token 在线返回 401）。

### 6.2 6 大核心维度检查矩阵

| # | 检查分类 | 检查项 | 检查方式与指标 | 针对性处理与建议 |
| :-: | :--- | :--- | :--- | :--- |
| **1** | **运行环境与依赖** | Python 环境、平台与 DPAPI 加密、核心依赖模块、安卓 ADB 工具 | `>= 3.8`；检测 Windows DPAPI 或 POSIX 权限；内置 `sqlite3`, `ssl`, `json`, `ctypes`, `threading`, `urllib` 完备性；PATH 中的 `adb` 探测 | 若已有有效凭据，ADB 缺失仅标记为 `INFO`，不降级为全局 `WARNING` |
| **2** | **本地存储与配置** | 工作目录写权限、SQLite 状态库、config.json、timetable.json | 实测 `data/`, `logs/`, `captures/` 可写性；`PRAGMA integrity_check;` 校验 `registration.db` 结构与记录数；解析目标课程与轮询配置；验证 `week1_monday` 与总周数 | 数据库损坏提示重置；未配置提示默认值 |
| **3** | **本地认证材料** | credential.json 存在性、DACL 保护、DPAPI 往返解密、字段完整性、账号脱敏 | 检查文件与权限；测试 DPAPI 解密能否还原明文；校验 `account`、`signDigital` 字段；计算签名摘要 | 损坏提示 `reinit`；明文提示升级 DPAPI 硬件加密 |
| **4** | **本地会话状态** | state.json 存在性、学校/学期标识、Token 生命周期、RefreshToken 状态 | 验证 `schoolId` 与 `semesterId`；根据 `accessTokenExpires` 计算精确剩余小时/分钟；检查 `refreshToken` 是否支持静默刷新 | 已过期提示静默刷新；无 RT 提示快速登录 |

### 6.3 统一命令行入口与多种输出形态
- **控制台文本形态**：`python lejian.py doctor` 或 `python lejian.py --doctor`（分组结构化、带状态图示）；
- **机器可读形态**：`python lejian.py doctor --json`（提供标准 JSON 格式输出，便于 CI/CD、脚本集成与自动化监控）；
- **主菜单集成**：`menu.py` 增加 `[d] 系统健康体检（只读诊断报告）` 选项；
- **参数控制**：支持 `-v`/`--verbose`（显示更详尽的诊断详情）、`--offline`（离线跳过在线网络验真）。
