# Phase 0 调研清单

目标：搞清楚「乐健体育」选课到底走什么接口，以及有没有风控。

**按顺序做，第 0 步可能直接让你跳过全部抓包工作。**

---

## 第 0 步：先确认是不是非抓包不可（5 分钟）

在动手装抓包工具之前，先排掉三种「根本不用抓包」的可能：

- [ ] 问学长/辅导员：学校体育选课**有没有网页端**？
- [ ] 电脑浏览器直接打开学校教务系统或体育部网站，找「体育选课」「选课」入口
- [ ] 打开乐健体育 App 的选课页，看界面像不像网页（滚动卡顿、字体异常、能长按出现「在浏览器中打开」）

**任意一条成立 → 用 Chrome 按 F12 打开 Network 就能看到接口，跳过第 1、2 步。**

很多校园 App 的选课页就是套了一层 WebView，真正的接口在网页端。这是最省事的情况。

---

## 第 1 步：真机 + Reqable 试抓（30 分钟）

这是成本最低的一次尝试，先看能不能抓到明文。

1. 手机和电脑连**同一个 WiFi**
2. 电脑安装 **Reqable**（reqable.com，免费版够用），启动抓包，记下代理地址，形如 `192.168.x.x:9000`
3. 手机 WiFi 设置 → 代理 → 手动 → 填上面的 IP 和端口
4. 手机浏览器访问 `reqable.com/cert` 下载并安装证书（安卓会提示「凭据用途」，选「VPN 和应用」）
5. 打开乐健体育，进选课页，点一次「查询」或刷新列表
6. 回到 Reqable 看记录：

| 现象 | 结论 | 下一步 |
|---|---|---|
| 能看到 `https://...` 明文请求和 JSON 响应 | ✅ 成功 | 导出 HAR，跳到第 3 步 |
| 只有 `CONNECT` 隧道、显示 unknown、或 App 报网络错误 | ❌ 有证书校验 / pinning | 走第 2 步 |
| App 直接无法联网 | 代理被检测 | 走第 2 步 |

**注意：Android 7 以后，App 默认不信任用户安装的证书。** 所以第 1 步失败很正常，不代表没戏。

---

## 第 2 步：模拟器 + 系统证书（1–2 小时）

目标是把证书装进**系统证书区**，让 App 认为它是合法的。

1. 安装 **MuMu 模拟器 12**（或雷电 9），在设置里开启 **root 权限**
2. 模拟器内安装乐健体育 APK
   - APK 从官网或应用商店下载；也可以 `adb install xxx.apk`
   - 若模拟器是 x86 架构而 APK 仅支持 arm，安装会失败 → 换雷电 9 的 arm 兼容模式，或改用真机 root
3. 把抓包工具的 CA 证书导入系统证书区：
   - 拿到证书 `.pem` / `.crt`
   - 计算 hash：`openssl x509 -inform PEM -subject_hash_old -in cert.pem | head -1`
   - 改名成 `<hash>.0`，推到 `/system/etc/security/cacerts/`，权限 `644`
   - 高版本 Android 的 `/system` 只读，需要 `adb root` + `adb remount`
   - **更省事**：Magisk 模块「Move Certificates」自动搬运，或 Reqable 的「模拟器一键安装」功能
4. 重复第 1 步的第 5、6 项

如果这一步也失败（证书绑定是写在 so 里的），那就**放弃抓包路线**，退回 UI 自动化方案（见文末）。

---

## 第 3 步：记录清单（对着 Reqable 一条条填）

抓到包后，把这些抄下来或截图：

### 登录
- [ ] 登录接口 URL、method
- [ ] 请求体字段（手机号？密码是否加密？）
- [ ] 返回里 token / cookie 的字段名
- [ ] **token 有效期**（重要：决定 13:50 要不要重新登录）

### 课程
- [ ] 课程列表 / 余量查询接口
- [ ] 返回结构长什么样（课程 ID、教学班 ID、余量字段名）

### 提交选课
- [ ] 提交接口 URL、method
- [ ] **完整请求体**（这是核心）
- [ ] 请求头里除了 token 还有没有特殊字段（`sign`、`timestamp`、`nonce`、`deviceId`、`appVersion`）
- [ ] 有没有 `sign` —— 如果有，它随什么变化？每次请求都不同吗？
- [ ] 成功响应样例（存一份）
- [ ] 失败响应样例：课程已满 / 重复选课 / 未开放（各存一份）

### 时间
- [ ] 任选一个接口，看响应头 `Date`，和手机时间差多少

---

## 第 4 步：交付

- 在 Reqable 里选中相关请求 → 右键 → 导出 → **HAR 格式**
- 存成 `captures/2026-10-xx-选课.har` 放到项目目录
- 截图也一并发我（尤其是提交选课的完整请求体）

我拿到 HAR 就能判断：
- 接口是否可直接调用
- 有没有签名
- 抢课窗口的精确判定条件
- 该做 Phase 2 还是退回 UI 自动化

---

## 兜底方案：抓不到包怎么办

如果第 1、2 步都失败，说明 App 有强保护。此时还有两条路：

**A. UI 自动化（uiautomator2）**
不碰网络层，直接让程序操控安卓界面点击。缺点：慢（每次点击 300–800ms）、界面改版就失效。但对「比别人快」仍有帮助——可以提前停在选课页、同时监听多个按钮、失败立即点下一个。

**B. 半自动**
只做「开抢时刻提醒 + 一键跳转选课页」，剩下你手点。几乎零风险，但速度提升有限。

选哪条，等抓包结果出来再定。

---

## 安全提醒

- 抓包只在**自己的设备和自己的账号**上做
- 不要用别人的账号测试，也不要分享抓到的 token
- HAR 文件里含登录态，别发群里、别传网盘
