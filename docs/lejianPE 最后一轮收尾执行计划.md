# 二、任务一：让 Gitleaks 成为真正的 CI 安全门禁

**优先级：P0**

修改文件：

```
.github/workflows/tests.yml
```

### 2.1 当前问题

目前配置：

```
- name: Run Gitleaks
  uses: gitleaks/gitleaks-action@v2
  env:
    GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
  continue-on-error: true
```

存在两个问题：

1. `continue-on-error: true` 允许扫描失败后 CI 继续通过。
2. 当前 Action 日志使用 `--log-opts=-1`，只能扫描最新提交相关内容，不能据此认定完整 Git 历史已经扫描。

虽然最新扫描显示 `No leaks found`，但安全检查尚未形成可靠的强制门禁。

### 2.2 修改要求

**要求 A：取消错误忽略**

删除：

```
continue-on-error: true
```

任何 Gitleaks 扫描失败或发现泄漏，都必须使 Security Scan Job 失败。

**要求 B：扫描当前工作树**

对当前仓库文件进行完整扫描。

包括：

- Python 源代码。
- JSON 配置及示例。
- YAML 工作流。
- Markdown 文档。
- 其他可能包含凭据的文本文件。

确保扫描结果能够被 CI 正确识别。

**要求 C：扫描完整 Git 历史**

当前 Checkout 已经配置：

```
with:
  fetch-depth: 0
```

保留完整历史获取配置。

使用当前 Gitleaks 版本支持的 Git 历史扫描命令，确保扫描所有可访问提交，而不是仅扫描最新一次提交。

注意：

- 不要使用限制为最近一个 Commit 的参数。
- 不要仅凭 fetch-depth=0 就认定扫描完整历史。
- 明确区分工作树扫描和 Git 历史扫描。
- 检查扫描命令的实际参数和执行日志。

**要求 D：验证安全门禁确实有效**

不要只检查扫描通过。

需要进行隔离验证：

1. 创建临时测试仓库。
2. 写入一个能够被 Gitleaks 默认规则识别的模拟凭据。
3. 分别验证工作树扫描和 Git 历史扫描。
4. 确认扫描发现模拟泄漏后返回非零退出码。
5. 验证完成后删除临时仓库。

不得将模拟凭据提交到真实项目仓库。

### 2.3 验收标准

- 

  移除 `continue-on-error: true`。

- 

  当前工作树扫描有效。

- 

  完整 Git 历史扫描有效。

- 

  模拟泄漏能够触发扫描失败。

- 

  正常仓库扫描通过。

- 

  Security Scan 成为真正的 CI 阻断门禁。

- 

  扫描失败时整个工作流不能显示为成功。

# 三、任务二：修复 compatibility.py 的编码降级问题

**优先级：P1**

修改文件：

```
timetable/compatibility.py
```

### 3.1 当前问题

当前文件顶部导入：

```
import datetime
import json
import os
import shutil
```

但是 `_safe_print()` 使用了：

```
enc = getattr(sys.stdout, "encoding", None) or "utf-8"
```

文件没有导入 `sys`。

这会导致：

1. 正常 UTF-8 输出时没有问题。
2. 当中文输出触发 `UnicodeEncodeError` 时，进入降级分支。
3. 因为 `sys` 未定义，触发 `NameError`。
4. 内部 `except Exception: pass` 又将错误吞掉。

因此当前函数虽然没有让程序崩溃，但降级输出实际上没有生效。

### 3.2 修改要求

**要求 A：修复导入**

在文件顶部增加：

```
import sys
```

**要求 B：完善安全输出**

保留原有 `_safe_print()` 的设计目标：

- 正常环境优先正常输出。
- 控制台编码不支持中文时进行安全降级。
- 不允许日志输出导致程序崩溃。
- 不允许因为降级失败而产生新的异常。

不要修改课表兼容、迁移及校验逻辑。

**要求 C：增加专项测试**

需要针对 `_safe_print()` 编写测试。

测试至少覆盖：

1. UTF-8 正常输出。
2. cp1252 不支持中文时的降级输出。
3. stdout 编码属性不存在时的处理。
4. 降级输出过程中再次出现异常时不会导致程序崩溃。

不能只通过设置 `PYTHONIOENCODING=utf-8` 验证，因为这无法覆盖真正的降级分支。

可以通过 Mock stdout 或自定义文本流模拟编码异常。

### 3.3 验收标准

- 

  补充 sys 导入。

- 

  UTF-8 输出正常。

- 

  cp1252 降级分支真实执行。

- 

  不产生 NameError。

- 

  不产生未捕获的 UnicodeEncodeError。

- 

  新增测试全部通过。

- 

  不影响旧版课表迁移逻辑。

# 四、任务三：将网络隔离提升为全局测试屏障

**优先级：P1**

修改范围：

- `tests/test_auth.py`
- 测试公共基础设施。
- `.github/workflows/tests.yml`
- 必要时调整测试启动入口。

### 4.1 当前问题

目前网络拦截写在：

```
tests/test_auth.py
```

实现方式：

```
class AuthTestSuite(unittest.TestCase):

    @classmethod
    def setUpClass(cls):
        import socket

        cls._orig_socket_connect = socket.socket.connect

        def guarded_connect(self, address):
            raise RuntimeError(
                "测试隔离屏障触发：单元测试严禁发起外部真实网络连接！"
            )

        socket.socket.connect = guarded_connect
```

问题在于：

该屏障只在 `AuthTestSuite` 执行期间生效。

其他测试模块不一定受到保护。

因此目前不能证明整个测试套件完全离线。

### 4.2 修改目标

建立全局测试网络隔离机制。

原则：

**允许本地测试通信，禁止外部真实网络访问。**

允许访问：

- `127.0.0.1`
- `localhost`
- `::1`

拒绝访问：

- 外部公网 IP。
- 外部域名。
- 乐健体育真实服务。
- 其他非本地网络地址。

### 4.3 实施要求

**要求 A：建立统一网络隔离模块**

建议新增：

```
tests/network_guard.py
```

统一负责测试期间的网络访问拦截。

不要继续依赖单个测试类的 `setUpClass()`。

**要求 B：覆盖常见网络入口**

至少考虑：

- `socket.socket.connect`
- `socket.create_connection`
- `socket.getaddrinfo`

确保通过 urllib、HTTP 客户端等常见方式发起的外部网络请求无法绕过屏障。

注意：

- 不能通过 DNS 查询外部域名。
- 不允许先进行真实 DNS 解析，再依赖 connect 拦截。
- 需要兼容 IPv4 和 IPv6 本地回环。
- 不要破坏本地 HTTP Server 测试。
- 如果项目存在 Unix Domain Socket 使用场景，不应误伤本地通信。

**要求 C：在整个测试运行之前启用**

推荐使用统一测试启动入口，例如：

```
tests/run_tests.py
```

启动顺序：

1. 安装全局网络隔离。
2. 加载所有测试模块。
3. 执行全部测试。
4. 输出测试结果。

GitHub Actions 必须使用同一个统一入口，不能绕过网络隔离直接运行测试。

**要求 D：增加网络隔离专项测试**

至少覆盖：

| 测试场景                 | 预期 |
| ------------------------ | ---- |
| 连接 127.0.0.1           | 允许 |
| 连接 localhost           | 允许 |
| 连接 ::1                 | 允许 |
| 连接公网 IP              | 拦截 |
| 解析外部域名             | 拦截 |
| 通过 urllib 请求本地服务 | 允许 |
| 通过 urllib 请求外部服务 | 拦截 |

外网拦截测试必须在真正建立网络连接之前完成。

**要求 E：兼容原有本地 HTTP 测试**

特别检查：

```
tests/test_timetable.py
```

其中存在本地 Web Editor API 测试，使用：

```
127.0.0.1
```

这些测试必须继续通过。

不要简单地禁止所有 socket 连接。

### 4.4 验收标准

- 

  网络隔离不再局限于 AuthTestSuite。

- 

  所有测试模块使用统一启动入口。

- 

  localhost 测试正常。

- 

  IPv4 回环正常。

- 

  IPv6 回环正常。

- 

  外部 IP 连接被拦截。

- 

  外部域名解析被拦截。

- 

  urllib 等常见网络请求无法绕过。

- 

  原有本地 HTTP 测试全部通过。

- 

  不访问任何真实乐健服务。
