-

-

- 

  如果修改应用层输出行为，保证不会影响日志文件的 UTF-8 写入。

- 

  不要为了让测试通过而删除中文日志。

推荐优先验证：

```

  PYTHONIOENCODING: utf-8
```

可以设置在测试 Job 或测试步骤级别。

**验收标准：**

### P1-02：消除自动化测试对真实网络的依赖

涉及：

- `core/auth_manager.py`
- `tests/test_auth.py`

**问题说明：**

当前 `save_state_atomically()` 无条件调用：

```
sem_id, year_range, sem_err = self.fetch_semester_info(
    access_token, school_id
)
```

即使 `login_data` 已经提供 `semesterId`，也会先尝试请求真实学期接口。

而 `tests/test_auth.py` 中：

- A25
- A26
- A27
- A28
- A29
- A32

这些测试调用 `save_state_atomically()` 时，没有统一 Mock `fetch_semester_info()`。

因此，测试可能访问真实的乐健体育服务端。

这与测试文档中声明的纯 Mock、无真实网络依赖不一致。

**执行任务：**

- 

  检查全部 `save_state_atomically()` 测试调用。

- 

  为相关测试统一 Mock `fetch_semester_info()`。

- 

  必要时 Mock 底层 `urllib.request.urlopen`。

- 

  确保测试不会访问 `cpes.legym.cn`。

- 

  检查其他测试模块是否存在同类问题。

- 

  考虑将学期信息获取依赖与状态保存逻辑进一步解耦。

- 

  评估已经存在有效 semesterId 时是否可以避免不必要的网络查询，但不能未经验证改变生产业务语义。

**建议增加一项防护测试：**

测试期间将真实网络访问替换为立即失败的 Mock。

如果任何单元测试意外触发网络请求，立即判定测试失败。

**验收标准：**

- 全部单元测试离线可运行。
- 不需要真实 Token。
- 不需要真实账号。
- 不需要连接乐健体育服务器。
- 测试结果不依赖服务端状态和网络质量。

### P1-03：修复备份失败被静默忽略的问题

涉及：

- `core/auth_manager.py`
- `core/credential_storage.py`
- `tests/test_auth.py`

**问题说明：**

目前两个模块在备份旧文件时都有类似逻辑：

```
try:
    shutil.copy2(old_path, backup_path)
except Exception:
    pass
```

这意味着：

即使 `.bak` 备份失败，程序仍然继续写入并替换原文件。

当前原子替换可以避免写入过程损坏原文件，但不能保证始终保留历史备份。

这与文档中强调的备份保护存在差距。

**执行任务：**

- 

  明确备份失败时的安全策略。

- 

  默认开启备份时，评估是否应在备份失败后拒绝覆盖旧文件。

- 

  如果采用 best-effort 备份，必须明确告警，不能静默忽略。

- 

  分别处理 state.json 和 credential.json。

- 

  检查临时文件清理。

- 

  检查备份文件是否可能被错误覆盖。

- 

  确保失败时旧文件内容保持不变。

**新增测试：**

| 场景             | 预期结果               |
| ---------------- | ---------------------- |
| 正常备份         | 旧文件生成 .bak        |
| 备份失败         | 按明确策略中止或告警   |
| 临时文件写入失败 | 旧文件不变             |
| JSON 回读失败    | 旧文件不变             |
| os.replace 失败  | 旧文件不变             |
| 连续保存         | 备份和最新状态均可恢复 |

**验收标准：**

任何保存失败都不能静默破坏用户原有的有效凭据或会话。
