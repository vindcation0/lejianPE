# 乐健体育 · 课外活动抢课工具

一个在 Windows 上运行的抢课脚本。通过直接调用乐健体育的接口，在每周日 14:00 活动开放报名时自动提交。

> **它抢的是【课外】里的活动**（户外跑、跳绳、排球、羽毛球、篮球……），
> **不是**体育主课程（如趣味田径），也不是会员制训练营。

📄 **接手或二次开发请先读**：[逆向与接口结论](docs/04-逆向与接口结论.md) —— 完整接口清单、抓包方法、业务规则与踩坑记录。

⚠️ **首次实战的故障复盘**：[2026-10-25 故障报告](docs/05-2026-10-25-故障报告.md) —— 开抢瞬间服务器崩溃的完整记录，以及为什么「响应码不可信」。

## 它能做什么

| 能力 | 说明 |
|---|---|
| 自动抢课 | 周日 14:00 活动一开放就提交，比手动快 |
| 会员制过滤 | 名字含「会员制」或地址含「需办会员」的活动一律跳过 |
| 课表冲突过滤 | 和你真实课表（含周次）对比，撞课的不抢 |
| 每周上限 | 每周最多 2 节 |
| 每天上限 | 每天最多 1 节 |
| 体质测试例外 | 体质健康测试不占上面两个名额 |
| 志愿降级 | 首选满了自动换下一个，按顺序 |
| 跨周正确 | 周日抢的是"下一周"的活动，用下一周的课表算冲突 |

## 规则边界

**会做**

- 只抢非会员制活动
- 只在活动报名窗口开放后提交
- 抢满上限自动停止

**不会做**

- 不看手机屏幕、不模拟点击，只发接口请求
- 不做多账号、不代抢
- 不绕过验证码
- 不在非报名窗口强行提交

**风险**：学校若认定脚本选课违规，最重可取消选课结果。请自行评估。

## 第一步：拿到 token

程序所有操作都靠 `state.json` 里的 token。项目现已支持**命令行账号密码直接登录**（主要方式），无需每次启动模拟器；同时完整保留模拟器同步作为备用通道。

### 方式一（推荐·主要方式）：命令行直接输入密码登录

在完成首次认证材料初始化后，日常登录仅需通过命令行输入密码即可完成认证：

1. 双击 `run.bat`
2. 选 **`[9] 账号密码登录（命令行·主要方式）`**（或直接运行 `python lejian.py login`）
3. 终端会提示输入密码（采用 `getpass` 机制，密码在输入时不回显、不落盘、不进日志）
4. 回车后自动派生时间戳、封装 AES 登录信封并提交服务端完成登录，自动拉取当前学期信息并原子生成 `state.json`。

> **首次认证材料初始化（只需做一次）：**
> 本地认证依赖于从一次合法登录中提取的 `signDigital` 签名材料。只需运行：
> ```bash
> python tools\login_cli.py --setup captures\login_flows.jsonl
> ```
> 即可生成脱敏的 `credential.json`。
> 
> **凭据安全与 DPAPI 加密：**
> - `credential.json` 包含关键认证签名，已被 `.gitignore` 严格忽略，**严禁上传公开仓库或与他人共享**。
> - 在 Windows 平台下，可运行 `python tools\login_cli.py --encrypt`，将签名通过 Windows DPAPI 加密，仅当前 Windows 登录用户可解密。
> - 只要不在 App 端修改密码，该签名可长期复用；若修改了密码，只需重新跑一次 `[b]` 重新抓取签名。

### 方式二（备用方式）：从模拟器 App 重新同步

若因认证协议变更或签名失效，可随时切换回模拟器备用通道：

1. 启动模拟器（MuMu 12 / 雷电等），打开乐健体育并确认已登录。
2. 双击 `run.bat` 选 **`[a] 从模拟器 App 同步 Token（备用方案）`**（或运行 `python tools\resync_from_app.py`）。
3. 程序自动通过 adb 提权拉取 App 本地数据库，解析并写入 `state.json`。

### 什么时候需要重新登录

只有 token **彻底失效**时才需要。按 `[8]` 如果报「刷新失败」，就是这种情况：

1. 双击 `run.bat` 选 `[9]` 输入密码重新登录即可。
2. 或在模拟器里重新登录后选 `[a]` 重新同步。

### token 的生命周期

| 项 | 说明 |
|---|---|
| accessToken 有效期 | 约 12 小时 |
| 自动续期 | 任何操作前，剩余不足 20 分钟就自动刷新 |
| refreshToken | 每次刷新会自动轮换，程序原子存回 `state.json` |
| refreshToken 有效期 | 长期有效，失效时通过 `[9]` 命令行重登即可 |

**结论：正常情况下程序全自动刷新 token，无需人工干预。**

## 第二步：配置课表

程序需要知道你的**真实课表**，才能判断抢到的课会不会撞课。
课表存储在 `timetable.json` 中，只记录你被占用的时段（星期、时间、生效周次），不保留任何无用的课程名称或教师信息。

### 方式 A（推荐）：网页可视化编辑器

双击 `run.bat` 选择 **`[t] 可视化编辑课表（网页版）`**，或运行：

```bash
python lejian.py editor
```

1. 程序会自动在本地启动安全的 HTTP 服务（仅监听 `127.0.0.1`，带随机会话 Token）并打开浏览器。
2. 页面展示直观的二维课表网格（星期一至星期日 × 时间段）。
3. 支持选择**每周、单周、双周或自定义周次**画笔，直接在格子上点击即可标记有课。
4. 支持自由添加、修改或删除时间段行（无需死记 45 或 90 分钟）。
5. 支持按周过滤预览（如对比第 8 周与第 9 周的占用差异）。
6. 编辑完成后点击「💾 保存课表」，系统自动执行数据格式校验并原子更新 `timetable.json`（自动备份旧课表为 `.bak`）。

### 方式 B（进阶）：从 Markdown 转换

如果你已有学校导出的 Markdown 课表文件，也可以直接转换：

```bash
python tools\build_timetable.py "C:\Users\你\Downloads\course_schedule.md" 8
```

- 第一个参数：课表 markdown 路径
- 第二个参数：**当前教学周**（用于换算第 1 周周一日期锚点）

### 周次感知

课表里 `1-8周`、`5-12周`、`单周` 这类周次会被严格保留并比对，所以：

- 第 8 周：周二早上被 1-8 周课程占着，程序判定冲突跳过；
- 第 9 周：该课程已结课，同一时段自动判定为可抢。

## 第三步：配置抢课规则

配置文件是 `config.json`，菜单里按 **`[c]`** 可以直接用记事本打开。

```json
{
  "targets": ["户外跑", "跳绳", "排球", "羽毛球", "篮球1"],
  "special": ["体质健康测试"],
  "exclude_member": true,
  "max_normal": 2,
  "max_per_day": 1,
  "watch_from": "13:59:00",
  "watch_until": "16:00:00",
  "poll_interval_ms": 500,
  "dry_run": true,
  "busy_slots": []
}
```

### 字段详解

| 字段 | 作用 | 建议 |
|---|---|---|
| `targets` | 想抢的课程，**顺序即优先级** | 必填 |
| `special` | 不占名额的特殊项关键字 | 一般不动 |
| `exclude_member` | 是否排除会员制活动 | 保持 `true` |
| `max_normal` | 每周最多几节 | `2` |
| `max_per_day` | 每天最多几节 | `1` |
| `watch_from` | 从几点开始盯着列表 | `13:59:00` |
| `watch_until` | 盯到几点放弃 | `16:00:00` |
| `poll_interval_ms` | 轮询间隔（毫秒） | `500` 够用，别低于 300 |
| `dry_run` | `true` 只演练不提交 | 首次务必 `true` |
| `busy_slots` | 手动补充的占用时段 | 一般留空，课表已覆盖 |
| `now_seconds` | `[4]` 立即模式持续几秒 | 默认 120，可不写 |

> **教学周次说明**：当前教学周由 `timetable.json` 中的 `week1_monday`（开学第一周周一）根据系统当前日期**全自动计算与推进**，无需在 `config.json` 里填写或每周手动修改。每学期仅需设定一次开学日期。

### targets 怎么写

三种写法都支持，数组顺序就是优先级：

```json
"targets": [
  "排球",
  {"keyword": "羽毛球", "teacher": "尹远洪"},
  {"keyword": "篮球1", "time": "16:00"}
]
```

| 写法 | 匹配方式 |
|---|---|
| `"排球"` | 课程名**包含**「排球」即可 |
| `{"keyword": "羽毛球", "teacher": "尹远洪"}` | 名字要同时含项目名和老师名 |
| `{"keyword": "篮球1", "time": "16:00"}` | 还要求活动**开始时间**正好 16:00 |

> 课程名的实际格式是「项目 + 老师」，如 `羽毛球 尹远洪`。
> 每周老师和场次都可能变，**填之前先用 `[7]` 看一眼当前有哪些名字**。

### busy_slots 什么时候用

课表已经覆盖了必修课，这个字段只是补充手段。比如临时有讲座要避开：

```json
"busy_slots": ["周三 19:00-21:00"]
```

格式 `周X HH:MM-HH:MM`。

## 界面说明

双击 `run.bat` 进入菜单：

```
==================================================
        乐健体育 · 课外活动抢课工具
==================================================

   [1]  查看 token 状态
   [2]  查看可抢活动（已按规则过滤）
   [3]  开始抢课（等到周日 14:00）
   [4]  立即抢课（不等周日）
   [5]  自检 20 秒（不会提交）
   [6]  查看课表与周次
   [t]  可视化编辑课表（网页版）
   [7]  查看所有课程名（填配置用）
   [8]  强制刷新 token
   [9]  账号密码登录（命令行·主要方式）
   [b]  重新抓取登录签名（改密码后用）
   [a]  从模拟器 App 同步 Token（备用方案）
   [c]  打开配置文件 config.json
   [0]  退出
```

### `[1]` 查看 token 状态

显示 token 还剩多久。**已经过期的话会自动尝试刷新**。

```
token 剩余 43199 秒 (约 12.0 小时)
schoolId=8a978047... semesterId=8a97802f... year=2026
有效
```

什么时候用：每周日开始前，扫一眼确认状态。

### `[2]` 查看可抢活动

**活动诊断与候选匹配。** 它负责检查可抢名额与筛选候选：
- 显示活动总数与当前教学周（根据日期自动推算）。
- 显示当前学期各周已报普通活动数量（如 `已报 1/2 节`）与特殊活动（如体测）情况。
- 内部自动结合你的课表、单双周设置、已抢活动与每日上限进行防冲突排查。
- 列出真正符合条件的可抢候选活动及其命中志愿的原因与开抢时间。不再刷屏输出课表明细。

```
活动总数 116  |  当前教学周：第 9 教学周
第9教学周 已报 1/2 节：
    户外跑 程启航  10-23 17:40
符合条件可抢 1 个：
  [1] 排球 贾建韬  周五 17:10~18:10  余1/50  开抢10-18 14:00  志愿3:排球
```

如果这里是 0 个，不代表出错，通常是：名额已满、与课表或已报活动撞时间、或者当天已经抢过一节。

### `[3]` 开始抢课（正式用）

它会一直等到**下一个周日**的 `watch_from`（默认 13:59），然后每 0.5 秒拉一次列表，一发现符合条件又处于报名窗口内的活动就立刻提交，抢满上限自动退出。

```
观察窗口 10-25 13:59:00 → 16:00:00
志愿 ['户外跑', '跳绳', ...] | 会员状态=unknown | dry_run=False
第 8 教学周，已占用 14 个时段：
  ...
>>> 成功！第9周 已报 1/2，10-30 当天第 1 节，额外 0
```

**启动时间建议 13:50 之前**，它会自己等到 13:59。

### `[4]` 立即抢课

不等到周日，立刻开始，持续 `now_seconds`（默认 120 秒）。

什么时候用：发现有活动当场的报名窗口还开着（比如体质健康测试漏了）。

### `[5]` 自检 20 秒

**强制 dry_run，绝不提交。** 用来验证：能不能连上接口、规则过滤是否正常、会不会识别出候选。

周日开抢前跑一次，确认链路是通的。

### `[6]` 查看课表与周次

**课表诊断与周次查看。** 专门负责展示学期全局配置与课表占用明细：
- 显示第一教学周周一的日期锚点。
- 显示学期总周数 `total_weeks`。
- 显示系统当前实际日期与推算出的当前教学周（并标明开学前/正常周/学期结束状态）。
- 分组列出**当前周**和**下一教学周**各自被课表及已抢活动占用的所有具体时段（按星期和时间从小到大排序）。

```
==================================================
                 课表与周次
==================================================

第一教学周周一：2026-08-31
学期总周数：16
当前日期：2026-11-01
当前教学周：第 9 周

---------------- 当前周 ----------------
第 9 周占用 13 个时段：
  周一 08:00~09:35 <- 大学英语
  周二 10:00~11:35 <- 高等数学

---------------- 下一周 ----------------
第 10 周占用 14 个时段：
  周一 08:00~09:35 <- 大学英语

==================================================
```

用它确认课表时间占用与周次是否准确——周次错一周，时间冲突判断就全错。

### `[7]` 查看所有课程名

列出当前所有**非会员制**课程名、场次和余量。填 `targets` 之前先看这个。

```
非会员活动 25 条，共 12 个课程名
  乒乓球室内 薛康平  [2场]  周五 17:10 余0 | 周五 16:00 余0
  羽毛球 尹远洪      [2场]  周五 17:10 余0 | 周五 16:00 余0
  跳绳 亢莉萍        [2场]  周五 17:10 余1 | 周五 16:00 余0
  ...
```

**每周都要重新看**，老师和场次会变。

### `[8]` 强制刷新 token

不管过期没有，立刻换一个新的。成功会写回 `state.json`。

失败的话说明 refreshToken 也失效了，走 `[9]` 重新命令行登录。

### `[9]` 账号密码登录（命令行·主要方式）

在终端中输入密码进行快速登录。不需要打开模拟器，密码输入时不回显，自动派生动态信封并生成合法 `state.json`。

### `[b]` 重新抓取登录签名（改密码后用）

若在官方 App 端修改了密码，签名材料失效时，可启动本项重新抓取并更新 `credential.json`。

### `[a]` 从模拟器 App 同步 Token（备用方案）

需要模拟器开着、App 已登录。自动完成 adb 连接、提权、拉数据库、解析、写 `state.json`。作为命令行登录的稳定备用入口。

### `[c]` 打开配置文件

用记事本打开 `config.json`。改完保存，回菜单重新选即可，不用重启。

### `[0]` 退出

## 周日的完整流程

| 时间 | 操作 | 目的 |
|---|---|---|
| 周六晚 | `[8]` | 确认 token 能刷新，别等到周日才发现 |
| 周日 13:45 | `[1]` | 确认 token 有效 |
| 周日 13:47 | `[2]` | 看当前列表（此时应该还是上周尾货） |
| 周日 13:50 | 改 `dry_run: false` | 正式抢才需要 |
| 周日 13:50 | `[3]` | 启动，程序等到 13:59 开始轮询 |
| 周日 14:00 | 自动 | 新批次出现，自动提交 |
| 周日 14:05 | `[2]` | 核对结果 |

### 第一次跑务必先演练

1. `dry_run` 保持 `true`
2. 周日 13:50 选 `[3]`
3. 看日志里它「准备抢什么」
4. 确认无误后，把 `dry_run` 改成 `false`，重新选 `[3]`

**注意**：14:00 之后改配置再启动，可能已经错过名额。所以建议 13:50 前就决定好。

## 常见问题

### 提示「刷新失败」

refreshToken 死了。模拟器里重新登录 App，然后跑 `[9]`。

### `[9]` 提示「没有连上设备」

模拟器没启动，或 adb 路径不对。先确认模拟器开着、App 开着。

### 可抢活动一直是 0 个

按顺序排查：

1. `[2]` 看「已报」是不是已经到上限
2. 看占用时段里是不是把目标时段占了
3. `[7]` 看目标课程是不是名字变了、或者已经满员

### 抢到了但日志显示失败

看 `logs\run-YYYYMMDD.log`，里面有完整的接口返回。常见原因：名额被别人抢先、当日已达上限。

### 周次好像不对

当前教学周由 `timetable.json` 中的 `week1_monday`（开学第一周周一）自动计算。

每学期只需要正确设置第一教学周周一的日期（必须是星期一），后续无需手动修改教学周次，程序每周一会自动推进。

### 学期总周数设置 (total_weeks)

在 `timetable.json` 中配置了 `total_weeks`（默认 16 周），用于确定学期边界及可视化编辑器的周次筛选范围。
可以在网页可视化编辑器（按 **`[t]`** 或运行 `python lejian.py editor`）顶部直接修改学期总周数，保存时会自动持久化并安全校验，绝不会静默截断已有的课表周次数据。

### 电脑睡眠会怎样

程序在睡眠时不会执行，醒来后会继续。抢课窗口内请把电源设置改成「从不睡眠」。

## 调用方高可用与可靠性体系

> 核心设计原则：**宁可少发，不可重复；发完必复核。**

针对学校服务器在瞬时并发下的网关回程失败（如 502/503）、高延迟超时（15s）、多实例并发提交等恶劣场景，系统构建了完整的可靠性闭环：

### 1. 报名状态机与 SQLite 持久化
- **状态流转**：`PENDING` → `SUBMITTING` → `SUCCESS` / `FAILED` / `UNKNOWN` → `VERIFYING` → `SUCCESS` / `RETRYABLE`
- **提交前事务保护**：提交请求发送前必须先在本地 SQLite 中写入 `SUBMITTING`；
- **响应不可信保护**：遇到 500、502、503、-1 超时或异常响应时，状态置为 `UNKNOWN`，**严禁直接重试**；系统立即触发 `isRegister` 服务端真实状态复核；若服务端已确认落库则升级为 `SUCCESS`，若确认未落库且满足规则才置为 `RETRYABLE`。
- **本地去重**：本地已是 `SUCCESS` 的活动绝对不重复发起提交。

### 2. 操作系统级单实例锁
- 使用 OS 级文件锁（Windows 下为 `msvcrt.locking`，POSIX 下为 `fcntl.flock`）；
- `grab` 与 `grab now` 必须获得锁才允许启动，彻底解决多个进程同时提交导致突破每周上限的问题；
- 程序异常崩溃或被终止时，操作系统自动回收文件句柄并释放锁，绝不会因为遗留 lock 文件导致无法启动。

### 3. 指数退避与健康状态机
- 系统维护服务健康状态：`NORMAL`（正常）、`DEGRADED`（降级退避）、`RECOVERING`（恢复对账中）；
- 查询接口连续失败触发指数退避：`delay = min(max_delay, base_delay * 2^(fail-1)) + jitter`；
- 收到 HTTP 429 优先遵守 `Retry-After` 要求，避免给服务器雪上加霜。

### 4. 崩溃恢复与最终全局核对
- **启动恢复**：程序启动时主动扫描 SQLite 中未决状态（`SUBMITTING`、`UNKNOWN`、`VERIFYING`），逐一向服务端求证真实状态，恢复为 `SUCCESS` 或 `RETRYABLE`；
- **全局核对**：当单周满额或观察窗口结束时，拉取服务端最终已报活动列表，按教学周和日期核实 `isRegister`；
- **超额告警**：若发现因服务端并发放行导致报名超过 `max_normal` 或 `max_per_day`，立即在终端与日志中发出显著告警，并彻底阻断后续提交，提示用户使用 `tools/cancel_one.py` 人工确认退课。

### 5. 独立请求审计日志
- 写入 `logs/requests-YYYYMMDD.jsonl`，记录每次报名操作的完整耗时、HTTP 状态、业务状态、是否复核与最终状态；
- 敏感数据自动脱敏：不记录 Token、学号、手机号与姓名。

### 6. 运行自动化测试
无需真实学校服务器凭据，直接运行完整测试套件：
```bash
python tests/test_reliability.py
```
覆盖 T01~T15 全部 15 种故障注入与可靠性测试（包含 503 复核成功、超时复核未知、多实例竞争、崩溃恢复、退避等）。

### 关于 state.json 的安全

`state.json` 里有你的 accessToken、refreshToken、学号、手机号。

- 不要发给别人
- 不要传到网盘或 Git
- 失效了也不影响，重新同步即可

## 已知限制

- **只对本人账号有效**，不处理多账号
- **活动列表结构可能变**，若接口改版需重新适配
- **报名窗口由服务器控制**，程序只能在窗口内提交，不能提前
- **已结束的活动不会参与冲突判断**（它们已从列表消失），但也不影响
- **体质健康测试**默认不占任何名额；若实际也受「一天一节」限制，需调整规则
