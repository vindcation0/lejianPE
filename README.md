# 乐健体育 · 课外活动抢课工具

一个在 Windows 上运行的抢课脚本。通过直接调用乐健体育的接口，在每周日 14:00 活动开放报名时自动提交。

> **它抢的是【课外】里的活动**（户外跑、跳绳、排球、羽毛球、篮球……），
> **不是**体育主课程（如趣味田径），也不是会员制训练营。

## 它能做什么

| 能力 | 说明 |
|---|---|
| 自动抢课 | 周日 14:00 活动一开放就提交，比手动快 |
| 会员制过滤 | 名字含「会员制」或地址含「需办会员」的活动一律跳过 |
| 课表冲突过滤 | 和你真实课表（含周次）对比，撞课的不抢 |
| 每周上限 | 每周最多 2 节 |
| 每天上限 | 每天最多 1 节 |
| 体质测试例外 | 体质健康测试不占上面两个名额 |
| 志愿降级 | 首选满了自动换下一个，按顺序 |
| 跨周正确 | 周日抢的是"下一周"的活动，用下一周的课表算冲突 |

## 规则边界

**会做**

- 只抢非会员制活动
- 只在活动报名窗口开放后提交
- 抢满上限自动停止

**不会做**

- 不看手机屏幕、不模拟点击，只发接口请求
- 不做多账号、不代抢
- 不绕过验证码
- 不在非报名窗口强行提交

**风险**：学校若认定脚本选课违规，最重可取消选课结果。请自行评估。

## 准备工作

| 需要 | 说明 |
|---|---|
| Windows 电脑 | Win10/11 均可，需装 Python 3.10+ |
| 安卓模拟器 | MuMu 模拟器 12（本项目在 `D:\MuMuPlayer` 验证通过） |

## 第一步：拿到 token

程序所有操作都靠 `state.json` 里的 token。它来自模拟器里 App 的本地数据库。

### 首次获取

1. 启动模拟器，打开乐健体育，确认已登录（能进首页）
2. 双击 `run.bat`
3. 选 **`[9] 从模拟器 App 重新同步 token`**

它会自动完成：连接 adb → 提权 → 拉取 App 数据库 → 解析 token → 写入 `state.json`。

成功后会显示：

```
已更新 state.json
  schoolId=8a978047...
  token 有效期至 2026-10-24 03:09:21
```

### 什么时候需要重新同步

只有 token **彻底失效**时才需要。按 `[8]` 如果报「刷新失败」，就是这种情况：

1. 打开模拟器里的乐健体育，**重新登录一次**
2. 再跑 `[9]`

### token 的生命周期

| 项 | 说明 |
|---|---|
| accessToken 有效期 | 约 12 小时 |
| 自动续期 | 任何操作前，剩余不足 20 分钟就自动刷新 |
| refreshToken | 每次刷新会轮换，程序自动存回 `state.json` |
| refreshToken 有效期 | 未知，实测连续刷新多次正常 |

**结论：正常情况下你永远不用手动管 token。**

只有在「周日 14:00 前发现刷新失败」时才需要走一次重新登录。

## 第二步：配置课表

程序需要知道你的**真实课表**，才能判断抢到的课会不会撞课。

课表来自 `timetable.json`，由学校导出的 markdown 生成。

### 生成方法

```bash
python tools\build_timetable.py "C:\Users\你\Downloads\course_schedule.md" 8
```

- 第一个参数：课表 markdown 路径
- 第二个参数：**当前教学周**（写错会导致周次判断错位）

输出：

```
解析 15 条，写入 ...\timetable.json

  周1 09:55-12:20  [1-16周]  概率论与数理统计A_37
  周1 14:00-15:35  [1-16周]  大学体育III_24
  周2 08:00-09:35  [1-8周]  国家安全教育_30
  ...
```

### 周次感知

课表里 `1-8周`、`5-12周`、`1-4周` 这类周次会被保留。程序按**活动自己所在的周**去比对，所以：

- 第 8 周：周二早上被《国家安全教育》占着
- 第 9 周：那门课已结课，周二早上空出来

同一个时段在不同周结论不同，这是刻意做的。

### 换学期或课表变了

重新跑一次 `build_timetable.py` 即可，同时把 `config.json` 里的 `current_week` 改成当前周。

## 第三步：配置抢课规则

配置文件是 `config.json`，菜单里按 **`[c]`** 可以直接用记事本打开。

```json
{
  "targets": ["户外跑", "跳绳", "排球", "羽毛球", "篮球1"],
  "special": ["体质健康测试"],
  "exclude_member": true,
  "max_normal": 2,
  "max_per_day": 1,
  "current_week": 8,
  "watch_from": "13:59:00",
  "watch_until": "16:00:00",
  "poll_interval_ms": 500,
  "dry_run": true,
  "busy_slots": []
}
```

### 字段详解

| 字段 | 作用 | 建议 |
|---|---|---|
| `targets` | 想抢的课程，**顺序即优先级** | 必填 |
| `special` | 不占名额的特殊项关键字 | 一般不动 |
| `exclude_member` | 是否排除会员制活动 | 保持 `true` |
| `max_normal` | 每周最多几节 | `2` |
| `max_per_day` | 每天最多几节 | `1` |
| `current_week` | 当前教学周 | 每周日过后 +1 |
| `watch_from` | 从几点开始盯着列表 | `13:59:00` |
| `watch_until` | 盯到几点放弃 | `16:00:00` |
| `poll_interval_ms` | 轮询间隔（毫秒） | `500` 够用，别低于 300 |
| `dry_run` | `true` 只演练不提交 | 首次务必 `true` |
| `busy_slots` | 手动补充的占用时段 | 一般留空，课表已覆盖 |
| `now_seconds` | `[4]` 立即模式持续几秒 | 默认 120，可不写 |

### targets 怎么写

三种写法都支持，数组顺序就是优先级：

```json
"targets": [
  "排球",
  {"keyword": "羽毛球", "teacher": "尹远洪"},
  {"keyword": "篮球1", "time": "16:00"}
]
```

| 写法 | 匹配方式 |
|---|---|
| `"排球"` | 课程名**包含**「排球」即可 |
| `{"keyword": "羽毛球", "teacher": "尹远洪"}` | 名字要同时含项目名和老师名 |
| `{"keyword": "篮球1", "time": "16:00"}` | 还要求活动**开始时间**正好 16:00 |

> 课程名的实际格式是「项目 + 老师」，如 `羽毛球 尹远洪`。
> 每周老师和场次都可能变，**填之前先用 `[7]` 看一眼当前有哪些名字**。

### busy_slots 什么时候用

课表已经覆盖了必修课，这个字段只是补充手段。比如临时有讲座要避开：

```json
"busy_slots": ["周三 19:00-21:00"]
```

格式 `周X HH:MM-HH:MM`。

## 界面说明

双击 `run.bat` 进入菜单：

```
==================================================
        乐健体育 · 课外活动抢课工具
==================================================

   [1]  查看 token 状态
   [2]  查看可抢活动（已按规则过滤）
   [3]  开始抢课（等到周日 14:00）
   [4]  立即抢课（不等周日）
   [5]  自检 20 秒（不会提交）
   [6]  查看课表与周次
   [7]  查看所有课程名（填配置用）
   [8]  强制刷新 token
   [9]  从模拟器 App 重新同步 token
   [c]  打开配置文件 config.json
   [0]  退出
```

### `[1]` 查看 token 状态

显示 token 还剩多久。**已经过期的话会自动尝试刷新**。

```
token 剩余 43199 秒 (约 12.0 小时)
schoolId=8a978047... semesterId=8a97802f... year=2026
有效
```

什么时候用：每周日开始前，扫一眼确认状态。

### `[2]` 查看可抢活动

**最常用的诊断命令。** 它会列出：当前占用的时段、你已报的节数、以及过滤后真正能抢的候选。

```
活动总数 116  |  第 8 教学周，已占用 15 个时段
  周一 14:00~15:35  <- 大学体育III_24（第8周）
  周五 09:55~12:20  <- 离散数学_01（第8周）
  ...
第8教学周 已报 1/2 节：
    户外跑 程启航  10-23 17:40
符合条件可抢 1 个：
  [1] 排球 贾建韬  周五 17:10~18:10  余1/50  开抢10-18 14:00  志愿3:排球
```

看三样东西：

1. **占用的时段对不对** —— 周次、课程是否和你实际课表一致
2. **已报几节** —— 每周/每天的上限有没有算对
3. **`[n]` 编号** —— 就是 `targets` 里的第几志愿，确认匹配没错

如果这里是 0 个，不代表出错，通常是：名额满了、撞课、或当天已经抢过一节。

### `[3]` 开始抢课（正式用）

它会一直等到**下一个周日**的 `watch_from`（默认 13:59），然后每 0.5 秒拉一次列表，一发现符合条件又处于报名窗口内的活动就立刻提交，抢满上限自动退出。

```
观察窗口 10-25 13:59:00 → 16:00:00
志愿 ['户外跑', '跳绳', ...] | 会员状态=unknown | dry_run=False
第 8 教学周，已占用 14 个时段：
  ...
>>> 成功！第9周 已报 1/2，10-30 当天第 1 节，额外 0
```

**启动时间建议 13:50 之前**，它会自己等到 13:59。

### `[4]` 立即抢课

不等到周日，立刻开始，持续 `now_seconds`（默认 120 秒）。

什么时候用：发现有活动当场的报名窗口还开着（比如体质健康测试漏了）。

### `[5]` 自检 20 秒

**强制 dry_run，绝不提交。** 用来验证：能不能连上接口、规则过滤是否正常、会不会识别出候选。

周日开抢前跑一次，确认链路是通的。

### `[6]` 查看课表与周次

打印当前是第几周、第 1 周周一的锚点，以及**第 8 周和第 9 周**各自占用的时段（包含已抢到的活动）。

```
当前第 8 教学周（第 1 周周一 = 2026-08-31，共 15 门课）
第8周占用 15 个时段：
  周五 17:40~18:35  <- 已抢:户外跑 程启航
第9周占用 13 个时段：
  ...
```

用它确认周次没错——周次错一周，冲突判断就全错。

### `[7]` 查看所有课程名

列出当前所有**非会员制**课程名、场次和余量。填 `targets` 之前先看这个。

```
非会员活动 25 条，共 12 个课程名
  乒乓球室内 薛康平  [2场]  周五 17:10 余0 | 周五 16:00 余0
  羽毛球 尹远洪      [2场]  周五 17:10 余0 | 周五 16:00 余0
  跳绳 亢莉萍        [2场]  周五 17:10 余1 | 周五 16:00 余0
  ...
```

**每周都要重新看**，老师和场次会变。

### `[8]` 强制刷新 token

不管过期没有，立刻换一个新的。成功会写回 `state.json`。

失败的话说明 refreshToken 也失效了，走 `[9]`。

### `[9]` 从模拟器 App 重新同步 token

需要模拟器开着、App 已登录。自动完成 adb 连接、提权、拉数据库、解析、写 `state.json`。

### `[c]` 打开配置文件

用记事本打开 `config.json`。改完保存，回菜单重新选即可，不用重启。

### `[0]` 退出

## 周日的完整流程

| 时间 | 操作 | 目的 |
|---|---|---|
| 周六晚 | `[8]` | 确认 token 能刷新，别等到周日才发现 |
| 周日 13:45 | `[1]` | 确认 token 有效 |
| 周日 13:47 | `[2]` | 看当前列表（此时应该还是上周尾货） |
| 周日 13:50 | 改 `dry_run: false` | 正式抢才需要 |
| 周日 13:50 | `[3]` | 启动，程序等到 13:59 开始轮询 |
| 周日 14:00 | 自动 | 新批次出现，自动提交 |
| 周日 14:05 | `[2]` | 核对结果 |

### 第一次跑务必先演练

1. `dry_run` 保持 `true`
2. 周日 13:50 选 `[3]`
3. 看日志里它「准备抢什么」
4. 确认无误后，把 `dry_run` 改成 `false`，重新选 `[3]`

**注意**：14:00 之后改配置再启动，可能已经错过名额。所以建议 13:50 前就决定好。

## 常见问题

### 提示「刷新失败」

refreshToken 死了。模拟器里重新登录 App，然后跑 `[9]`。

### `[9]` 提示「没有连上设备」

模拟器没启动，或 adb 路径不对。先确认模拟器开着、App 开着。

### 可抢活动一直是 0 个

按顺序排查：

1. `[2]` 看「已报」是不是已经到上限
2. 看占用时段里是不是把目标时段占了
3. `[7]` 看目标课程是不是名字变了、或者已经满员

### 抢到了但日志显示失败

看 `logs\run-YYYYMMDD.log`，里面有完整的接口返回。常见原因：名额被别人抢先、当日已达上限。

### 周次好像不对

改 `config.json` 的 `current_week`，然后重跑 `build_timetable.py`。

判断方法：用一门有明确周次的课验证，比如「国家安全教育（1-8周）」——这周还在上就是第 8 周（或更早），已经结了就是第 9 周以后。

### 电脑睡眠会怎样

程序在睡眠时不会执行，醒来后会继续。抢课窗口内请把电源设置改成「从不睡眠」。

├─ run.bat                 入口，双击运行

### 关于 state.json 的安全

`state.json` 里有你的 accessToken、refreshToken、学号、手机号。

- 不要发给别人
- 不要传到网盘或 Git
- 失效了也不影响，重新同步即可

## 已知限制

- **只对本人账号有效**，不处理多账号
- **活动列表结构可能变**，若接口改版需重新适配
- **报名窗口由服务器控制**，程序只能在窗口内提交，不能提前
- **已结束的活动不会参与冲突判断**（它们已从列表消失），但也不影响
- **体质健康测试**默认不占任何名额；若实际也受「一天一节」限制，需调整规则
